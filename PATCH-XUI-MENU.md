# Исправление управления Docker-панелью 3x-ui

Этот архив содержит только изменённые файлы, а не полную установку Nexus.
Он предназначен для проекта Nexus 2.7.5 с мастером локальных панелей.
Данные клиентов, базы, `.env` и `credentials.json` в архив не входят.

## Уже установленный сервер

1. Сохраните копии прежних `install.sh` и `scripts/local-panels.py`.
2. Замените эти файлы в `/opt/3xui-aggregator`, сохранив структуру каталогов.
   Тесты можно скопировать в одноимённый каталог, для работы меню они не нужны.
3. От root выполните:

```bash
python3 /opt/3xui-aggregator/scripts/local-panels.py install-cli --instance default
x-ui-default
```

Регистрация команд не переустанавливает панели, не меняет пароли и не
перезапускает контейнеры. После неё доступны `x-ui` и `xui`, если эти имена
не заняты другой установкой. Linux различает регистр: используйте строчные буквы.
При конфликте используйте `x-ui-default`. Для другого экземпляра укажите его имя
в `--instance` и используйте `x-ui-ИМЯ`.

## Команды

```bash
x-ui                 # Меню
x-ui status          # Статус только 3x-ui
x-ui credentials     # Сохранённые адрес, логин, пароль, токен, параметры Nexus
x-ui password        # Изменить логин/пароль с подтверждением
x-ui token           # Создать/перевыпустить CLI API-токен с подтверждением
x-ui start
x-ui stop
x-ui restart
x-ui logs
x-ui settings        # Посмотреть текущие настройки 3x-ui
```

Это меню для управляемой Docker-установки, а не оригинальный systemd-скрипт
3x-ui. Не устанавливайте поверх неё второй экземпляр официальным host-скриптом.
Смена логина/пароля и выдача токена кратковременно останавливают только 3x-ui
и её VPN-соединения. Перед изменением в `/opt/nexus-local-panels/default`
создаётся закрытая резервная копия базы и сохранённых данных входа.
Если 3x-ui была остановлена, изменение не запускает её автоматически.

### Данные входа и API-токен

При новой установке поддерживаемой версии токен создаётся один раз и
сохраняется вместе с данными входа в root-файле
`/opt/nexus-local-panels/default/3xui/credentials.json` (права 0600).
В конце установки секреты отображаются непосредственно в SSH-терминале,
не дублируясь в stdout установщика и его обычные журналы.
Не публикуйте скриншоты этого блока: запись SSH-сеанса также может их сохранить.
Без доступного TTY выводится только путь к файлу.

У ранее установленной панели токен самопроизвольно не создаётся:
вызовите `x-ui token`, если он нужен. В 3x-ui 3.7.0 CLI может перевыпустить
`cli-fallback` и сделать прежний токен недействительным. После перевыпуска
замените токен в подключении Nexus. Просмотр `credentials` никогда не
вызывает команду перевыпуска.

Если выбранная старая версия не поддерживает CLI выдачи токена, создайте
его в веб-настройках 3x-ui или используйте в Nexus вход по логину/паролю.
При изменении данных через веб-интерфейс сохранённый файл может устареть:
из хеша пароля/токена нельзя восстановить исходное значение.

Для подключения Nexus на том же VPS:

- API/Panel URL: `http://local-3xui:2053`.
- Panel Path: значение из вывода `credentials`.
- Авторизация: сохранённый API Token или логин/пароль.
- Inbound ID: ID inbound, который вы создадите в 3x-ui.

Это внутренний адрес Docker, не ссылка для браузера. Внутренние HTTP и порт
2053 менять не нужно: HTTPS снаружи обслуживает Caddy. Порты Xray публикуются
мастером, но inbound автоматически не создаётся.

## Исправление HTTPS по IP

Генератор теперь добавляет `default_sni` с выбранным IP в Caddyfile — и для
Nexus с доменом, и для отдельного Caddy в IP-режиме. Исправление восстанавливается
при генерации конфигурации/обновлении Nexus. Совпадающая ручная настройка
сохраняется; конфликтующая пользовательская настройка не перезаписывается.

На уже исправленном вручную сервере ничего менять в Caddy не нужно.
Замена файлов сама по себе не перезагружает конфигурацию работающего Caddy.
Локальный сертификат остаётся локальным: исправление SNI не делает его
автоматически доверенным для браузеров.

Проверки: модульные тесты используют временные файлы и имитацию Docker.
Полная установка на Linux/VPS в этой среде не запускалась.

Основание поведения CLI токена и смены пароля:
https://github.com/MHSanaei/3x-ui/blob/v3.7.0/main.go
