# Исправление лимитов узлов, подсказки шаблона и интерфейса

11 сентября 2026. Только изменённые файлы поверх предыдущего патча
`Nexus-Panel-users-preferences-pilot`. Его модули пользователей/пространств
должны уже находиться в проекте: этот архив их повторно не включает.

## Лимиты

Воспроизведены два дефекта прежнего кода Remnawave:

- Создать клиента с 50 ГБ на узле → синхронизировать без указания квоты →
  сохранённый лимит заменялся общим лимитом клиента, например 0.
- «Создать отсутствующих» не меняло квоту существующего удалённого пользователя,
  но могло записать общий лимит в локальную связь клиента с узлом.

Теперь синхронизация/продление сохраняют квоту связи `client_nodes`, включая
явный 0. Явное новое значение применяется как прежде. Восстановление отсутствующего
удалённого пользователя также использует сохранённую квоту его связи.

Общая форма создания/редактирования для всех провайдеров различает:

- **0** — безлимит на этом узле;
- **число**, например 50 или 12.5 — заданный лимит в ГБ;
- **пустое поле** — взять общий лимит клиента при сохранении;
- **поле не передано** при изменении — сохранить прежний лимит узла.

Редактор раньше превращал сохранённый 0 в пустую строку. Теперь показывает 0
явно: изменение комментария или общего лимита не отменяет безлимит другого узла.
Некорректные/отрицательные значения отклоняются до записи клиента.

В текущей интеграции Remnawave лимит задаётся пользователю всей удалённой панели,
а не отдельному Host/Squad. Не назначайте разные квоты одному удалённому
пользователю через несколько записей Nexus, ведущих в ту же Remnawave-панель.

**Если лимит уже сбросился ранее, обновление не угадает старое значение.**
Задайте его заново один раз. Ретроспективное восстановление возможно только
по вашим данным/резервной копии. Скрипт не меняет квоты массово при запуске.

## Шаблон инфо-блока

Под полем добавлен раскрывающийся список с пояснениями. Нажатие вставляет
подстановку в позицию курсора или вместо выделенного текста.

| Подстановка | Значение |
|---|---|
| `{login}` | Логин |
| `{display_name}` | Отображаемое имя клиента |
| `{device_usage}` | Устройства: использовано / лимит |
| `{device_count}` | Количество учтённых устройств |
| `{device_limit}` | Лимит устройств |
| `{ip_usage}` | Старое название `{device_usage}` — это НЕ число IP |
| `{limit_ip}` | Лимит IP |
| `{traffic_usage}` | Использованный трафик / лимит из данных подписки |
| `{days_left}` | Осталось дней |
| `{expiry_date}` | Дата окончания |
| `{support_note}` | Текст поддержки |

Это переменные, не исполняемые команды. Неизвестные `{имена}` остаются текстом.
Существующий лимит инфо-блока — 200 символов после подстановки: длинный текст
обрезается. Список проверяется тестом на совпадение с реальным обработчиком.

## Интерфейс

- «Сроки заканчиваются»: 3 колонки при ширине от 1440 px, 2 на промежуточной
  ширине, 1 до 900 px. Убраны дополнительные отступы, смещавшие соседние карточки.
- Основные кнопки публичной подписки, включая «Добавить» Happ/INCY и
  «Скопировать ссылку», имеют белый текст в светлой и тёмной темах.
- Обновлена версия CSS в ссылках, чтобы браузер подхватил исправление.

## Проверки

- На прежнем коде оба теста Remnawave воспроизводят сброс `50 → 0`.
  На исправленном проходят создание, синхронизация, продление, изменение
  квоты, явный безлимит и «создать отсутствующих».
- Используются реальные функции приложения и SQLite, удалённый API имитируется.
  Живые 3x-ui/Remnawave и рабочий VPS в этом сеансе не изменялись.
- В браузере проверены 1920 px (3 ровные колонки), 390 px (1 колонка без
  горизонтального переполнения), белый текст кнопок в обеих темах и вставка переменной.
- Проверены синтаксис JS и 19 шаблонов EJS.
- Общий набор: 163 теста; 155 успешно, 4 ошибки прежних функций, 4 пропуска.
  Оставшиеся: текст ошибки отсутствующего inbound, старое ожидание служебных
  узлов в Spectrum, сценарий истёкшей подписки/device-registry, fallback автовыбора.
  Тесты CSS больше не требуют устаревшую фиксированную версию кеша `270`.

## Обновление

1. Сделайте полный backup через `agg` → 5.
2. Замените файлы в репозитории с сохранением вложенных путей. Предыдущий патч
   пользователей/пространств должен быть установлен; иначе сначала примените его.
3. `agg` → 2, обновление с сохранением данных. Дополнительные панели — 0,
   оставить как есть. Переустановка не нужна.
4. Обновите страницу браузера. Проверьте тестового клиента: один узел 50 ГБ,
   другой 0, затем измените комментарий и продлите срок — квоты должны сохраниться.
   Ранее потерянные значения выставьте заново.
