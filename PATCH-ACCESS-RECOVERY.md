# Права главного администратора и окно отказа

12 сентября 2026. Изменённые/новые файлы поверх Nexus-Panel-502-dependencies-fix.
Не полный проект. Базы, .env, клиенты, узлы и пароли не входят в архив.

## Обновление

Сделайте резервную копию данных и .env. Загрузите всё содержимое архива в корень
проекта GitHub с сохранением папок. На сервере: agg → 2 (обновить с сохранением
данных), дополнительные панели → 0 (оставить как есть).

## Восстановить свои права

Миграция назначала владельцем аккаунт, совпадающий с ADMIN_USERNAME. Другие
старые аккаунты получали только просмотр. Это может затронуть владельца,
который входит под другим логином. Повторное изменение ADMIN_USERNAME не
изменяет уже созданный реестр control.db.

После обновления выведите список (без паролей и их хешей):

```bash
docker exec -w /app 3xui-aggregator node access-admin.js list
```

main_admin=1 — главный администратор, 0 — обычный пользователь.
Найдите СВОЙ точный логин, затем подставьте вместо ВАШ_ЛОГИН:

```bash
docker exec -w /app 3xui-aggregator node access-admin.js grant-owner 'ВАШ_ЛОГИН' --confirm
```

Это даёт выбранному существующему аккаунту полный доступ ко всем пространствам
и системным настройкам. Убедитесь, что выбрали свой аккаунт. Перед изменением
создаётся согласованная резервная копия control.db в migration-backups.
Пароль не меняется; другие пользователи не повышаются и не понижаются.
Заблокированные аккаунты команда не разблокирует. Повторное выполнение для
уже назначенного владельца ничего не меняет. Команда доступна только через
SSH/локальный запуск, HTTP-маршрута повышения прав нет.

После назначения выйдите из панели и войдите заново: прежние сессии этого
пользователя отозваны. В «Пользователи и доступ» выберите «Основное» —
системные настройки доступны именно в основном пространстве.

## Отказ в доступе

Обычные клики по внутренним ссылкам и отправка форм сначала проходят
неизменяющую данные проверку прав. При отказе текущая страница остаётся
открытой: появляется окно по центру с крупным текстом, кнопкой «Понятно»,
закрытием Escape и возвратом фокуса. Поля формы сохраняются.
API-запросы с отказом серверной проверки также вызывают окно.
Серверная авторизация остаётся обязательной, разрешение предварительной
проверки не заменяет повторную проверку при выполнении действия.

При прямом вводе запрещённого URL, открытии в новой вкладке, выключенном JS
или изменении прав между проверкой и действием возможна отдельная оформленная
страница 403. Автоматических переходов на чужие сайты нет.

Текст не называет любого пользователя «не администратором»: администратор
пространства тоже может не иметь системных прав. Показано точное сообщение:
«У вас нет прав для этого действия. Обратитесь к главному администратору».
