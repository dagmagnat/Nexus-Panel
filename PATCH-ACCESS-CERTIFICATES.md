# Доступ к панелям, API и сертификаты

Архив содержит только изменённые файлы для текущего Nexus 2.7.5.
Сделайте резервную копию и замените файлы с сохранением путей в репозитории.
После обычного обновления Nexus пересоберётся контейнер с исправлением API.
Новые файлы `lib_node_api_address.js` и тест обязательны в репозитории;
не заменяйте один `app.js` без нового модуля.

## Для уже установленного VPS

После обновления файлов в `/opt/3xui-aggregator` зарегистрируйте новую версию меню:

```bash
python3 /opt/3xui-aggregator/scripts/local-panels.py install-cli --instance default
x-ui-default
```

Переустановка 3x-ui не требуется. Новый пункт **10** и команда
`x-ui-default certificate` позволяют изменить домен/IP и сертификат.

## Сертификаты

- Домен: задайте отдельный поддомен 3x-ui, его A/AAAA должны указывать на VPS.
  Внешние TCP 80/443 должны быть доступны. Caddy получает и продлевает сертификат.
- Публичный IP: выберите публичный сертификат Let's Encrypt. Требуется публичный
  IP и внешний TCP 80. В этой конфигурации используется `caddy:2.11.0` с профилем
  `shortlived` и HTTP-01. HTTPS панели остаётся на её порту (например 2053).
  Короткоживущие сертификаты продлевает сам Caddy; оставьте TCP 80 доступным.
- Локальный IP-сертификат: доступен как отдельный явный выбор, но браузеры без
  доверия к локальному CA будут предупреждать о сертификате.

При первоначальной настройке/смене сертификата конфигурация Caddy пересоздаётся,
поэтому возможен краткий перерыв веб-доступа. Сам контейнер Nexus, 3x-ui и VPN
для этого не останавливаются. При очередном выпуске и продлении сертификатов
порты не освобождаются и другим процессам не передаются: проверки обслуживает
один Caddy. Это исключает гонку за портами между ACME-клиентами двух панелей.

Перед применением делается резервная копия конфигурации. При ошибке применения
старые файлы восстанавливаются и предпринимается запуск прежнего Caddy.
Неудачная выдача сертификата CA после запуска — асинхронная ошибка, она не
вызывает автоматический откат на локальный сертификат. Смотрите журнал:

```bash
docker logs --tail 80 3xui-aggregator-caddy
```

Сообщение «Конфигурация применена» не означает, что CA уже выдал сертификат.
Не запускайте второй certbot/acme.sh поверх этих же портов. Файлы SSL в самой
3x-ui настраивать не нужно: TLS завершается в Caddy, внутри Docker используется HTTP.

## Подключение Nexus к 3x-ui на этом же сервере

```text
API/Panel URL: http://local-3xui:2053
Panel Path: значение из x-ui-default credentials
API Token: сохранённый токен из той же команды
Inbound ID: ID вашего созданного inbound, а не произвольное число
```

Если токена нет, создайте его пунктом меню или выберите авторизацию по логину/паролю.
Внутренний HTTP не требует публичного сертификата; HTTPS нужен для внешнего доступа.
Не используйте `http://публичный-IP:2053` для порта, который обслуживает HTTPS.
Не используйте `https://local-3xui:2053`: внутри контейнера этот порт обслуживает HTTP.

Исправлено дублирование базового пути при вставке полного URL вместе с Panel Path.
Ответ HTML вместо JSON теперь считается ошибкой подключения. Для HTTP 400 выведены
подсказки по схеме/порту/пути, без публикации произвольного тела ответа сервера.
Точная причина конкретного HTTP 400 со скриншота без адреса и диагностики сервера
не подтверждена; эта ошибка не доказывает ни нехватку памяти, ни неправильный токен.

## Данные входа

В конце установки/обновления и восстановления выводятся сохранённые адрес, логин
и пароль Nexus, а также данные управляемой 3x-ui. Секреты направляются напрямую
в SSH-терминал, не в stdout/обычные журналы установщика. Не публикуйте этот блок.
Автоматическое обновление без терминала не раскрывает пароль в журнале.

Nexus показывает пароль из `.env`, 3x-ui — из root-файла `credentials.json`.
Если вы изменили данные в браузере, сохранённые значения могут устареть: из хеша
в базе нельзя восстановить пароль. Обновление и восстановление не сбрасывают
учётные данные молча. Восстановление не включает базы дополнительных панелей,
если их не резервировали отдельно.

Проверено модульными тестами и проверками синтаксиса. Docker Engine/VPS и реальная
выдача сертификата в этой среде недоступны; получение публичного сертификата нужно
подтвердить на сервере. Полный интеграционный тест приложения требует better-sqlite3.

Источники: [Caddy tls](https://caddyserver.com/docs/caddyfile/directives/tls),
[CertMagic 0.25.2](https://github.com/caddyserver/certmagic/blob/v0.25.2/acmeissuer.go).
