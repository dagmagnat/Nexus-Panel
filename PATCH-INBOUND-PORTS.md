# Порты выбранного inbound

Замените файлы из архива в репозитории, затем обновите Nexus через agg.
Обновление должно пересобрать приложение и сгенерировать Compose override,
чтобы Nexus получил NEXUS_LOCAL_XUI_VPN_PORTS. Простого restart недостаточно.

Добавление и редактирование узла читают выбранный Inbound ID через API 3x-ui.
Порт берётся именно из него. Для API local-3xui проверяется наличие публикации
порта/протокола в конфигурации установщика. При несовпадении сохранение
останавливается с понятным сообщением. Проверка не подменяет порт inbound.

Если нужен новый VPN-порт:

1. Создайте inbound в 3x-ui и запомните его порт и транспорт.
2. В SSH выполните `sudo x-ui ports` (для default также `sudo x-ui-default ports`).
3. Введите, например, `28140/tcp` для VLESS TCP/Reality и подтвердите ДА.
4. Повторите добавление узла в Nexus с ID этого inbound.

Enter в этом меню ничего не меняет. Старые публикации сохраняются. Занятый
порт не заменяется случайным: операция прекращается. Делаются резервные копии
конфигураций и откат при ошибке применения. Перезапускаются только локальная
3x-ui и Nexus; VPN-соединения кратковременно прервутся. Пароли, UUID и настройки
inbound не меняются. Панели, установленные вне этого мастера, не затрагиваются.

Это явная публикация через SSH, не автоматическое открытие портов из веб-панели.
Firewall провайдера и доступность извне проверяются отдельно. Ручные изменения
Docker за пределами мастера могут сделать сохранённый список публикаций
неактуальным. Порт 2053 — административный, не VPN-порт.

Проверки: 56 Python-тестов с имитацией Docker, 15 Node-тестов и проверка
синтаксиса app.js. Живой VPS/Docker в этой среде недоступен.
