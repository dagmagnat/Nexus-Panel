<h1 align="center">Nexus Panel</h1>

Nexus Panel объединяет узлы **3x-ui** и **Remnawave** в одной панели: клиенты, подписки, лимиты, трафик, маршрутизация, перенаправление, Telegram и резервные копии.

[![Version](https://img.shields.io/badge/version-2.7.5-blue)](https://github.com/dagmagnat/Nexus-Panel)
![Node.js](https://img.shields.io/badge/node-%3E%3D22-gray)
![License](https://img.shields.io/badge/license-MIT-gray)

## Что умеет панель

- подключать 3x-ui по API Token или логину и паролю;
- подключать Remnawave по API и Internal Squad;
- присоединять собственные Nexus Node по исходящему защищённому HTTPS-каналу без открытия админ-порта на VPS;
- загружать выбранный `Inbound ID`, включая VLESS, REALITY, TLS, XHTTP и расширенные параметры;
- создавать и синхронизировать клиентов с сохранением UUID;
- объединять серверы в SUB, Hiddify SUB и JSON-подписки;
- показывать общий и отдельный расход по каждому узлу, не смешивая лимит LTE с другими серверами;
- задавать общий лимит клиента или отдельный лимит ГБ для конкретного узла;
- группировать клиентов и назначать им цветные метки;
- выдавать фирменную веб-страницу подписки со сроком, трафиком и кнопками приложений;
- управлять GeoSite/GeoIP, маршрутизацией и правилами перенаправления;
- переносить настройки и клиентов, создавать и восстанавливать резервные копии;
- работать в адаптивном интерфейсе Nexus Spectrum Clear на компьютере и телефоне.

## Быстрая установка

Нужен Linux VPS с root-доступом. Для автоматического HTTPS домен должен указывать на сервер, а порты `80` и `443` должны быть свободны.

```bash
sudo -i curl -fsSL https://raw.githubusercontent.com/dagmagnat/Nexus-Panel/main/bootstrap.sh | bash
```

Если приглашение уже выглядит как `root@server:~#`, повторять `sudo -i` не нужно. Короткий bootstrap сам скачивает и проверяет основной установщик, исправляет CRLF и сохраняет интерактивный ввод. Журналы находятся в `/var/log/nexus-panel/`.

Установка из клонированного репозитория:

```bash
git clone https://github.com/dagmagnat/Nexus-Panel.git
cd Nexus-Panel
sudo bash install.sh
```

## Управление и обновление

```bash
# Открыть безопасное интерактивное меню
agg

# Обновить файлы панели с автоматическим backup
agg update
```

Пустой Enter в меню ничего не запускает. База `data/app.db`, `.env`, UUID, `sub_slug` и ранее выданные ссылки при обновлении сохраняются.

Если старый ярлык `agg` сообщает `set: pipefail` или показывает только шапку, восстановите его одной командой:

```bash
curl -fsSL https://raw.githubusercontent.com/dagmagnat/Nexus-Panel/main/bootstrap.sh | bash -s -- repair-shortcut && agg
```

Веб-обновление доступно в «Настройки → Обновление проекта». Оно проверяет новую версию, создаёт backup, заменяет только файлы проекта и перезапускает панель.

## Подписки и трафик

Галочка **«Начать после активации»** в создании/редактировании клиента запускает
срок после первого добавления подписки в приложение с HWID устройства. Например,
тест на 3 дня даёт полные 72 часа с активации. По умолчанию галочка снята.
Подробности: [Срок с активации устройства](docs/CLIENT_ACTIVATION.md).

Один адрес `/json/<slug>` работает в двух режимах: при обычном открытии в браузере он показывает фирменную страницу подписки, а VPN-приложение получает исходную JSON-конфигурацию. Это действует и для старых ссылок с `?raw=1`. Чтобы именно скачать JSON в браузере, добавьте `?download=1`.

«Открыть» по-прежнему ведёт прямо на `/open/<slug>`.

В «Настройки → Общие настройки» параметр «Показывать расход ГБ и срок в подписках» управляет только отображением цифр. Даже если показ выключен, заданные лимиты продолжают применяться.

Для LTE или другого ограниченного сервера задайте ГБ непосредственно в строке этого узла у клиента. Расход такого сервера считается отдельно и не включает трафик остальных узлов.

## GeoSite и GeoIP

В разделе «Маршрутизация» доступны:

- Loyalsoldier;
- Russia rules от runetfreedom с категориями `ru-blocked`, `ru-blocked-community`, `ru-whitelist` и другими;
- локальный источник клиента;
- собственные URL `geosite.dat` и `geoip.dat`.

Справочник обновляется автоматически через кэш и вручную кнопкой «Обновить список».

## Резервная копия и перенос

Настройки и клиенты переносятся отдельно. Сначала импортируйте настройки и узлы, затем клиентов.

```bash
# Зашифрованный пакет настроек
agg settings export /root/nexus-settings.nxsettings
agg settings inspect /root/nexus-settings.nxsettings
agg settings import /root/nexus-settings.nxsettings --dry-run
agg settings import /root/nexus-settings.nxsettings

# Клиенты
agg clients export /root/nexus-clients.json
agg clients inspect /root/nexus-clients.json
agg clients import /root/nexus-clients.json --dry-run
agg clients import /root/nexus-clients.json --mode update --node-mode match
```

Перед настоящим импортом Nexus создаёт резервную копию. Файлы переноса содержат секреты или идентификаторы клиентов — храните их как пароль и удаляйте после завершения переноса.

## Частые проблемы

### `Not found` при входе

Используйте `/login` или постоянный мобильный адрес `/mobile-login`. Дополнительный секретный ключ в URL не требуется. Если старый адрес закэширован браузером или прокси, очистите кэш и повторите вход по `/login`.

### Порт 80 уже занят

```bash
ss -ltnp | grep ':80 '
```

Не останавливайте Nginx/Caddy, если он обслуживает другие сайты: сначала настройте совместное проксирование или другой режим публикации.

### Узел показывает `0 ГБ`

Нажмите «Проверить» в карточке узла. Nexus читает сумму `up/down` выбранного inbound и, если агрегат равен нулю, дополнительно суммирует `clientStats` 3x-ui. Убедитесь, что указан правильный `Inbound ID` и API видит статистику именно этого inbound.

## Логотип и структура

Рабочие логотипы находятся в `public/img/`. Папка `branding/` содержит исходные материалы и нужна только для повторного экспорта; удаляйте её лишь если эти исходники вам точно не понадобятся.

- `app.js` — сервер и API;
- `views/` — EJS-интерфейс;
- `public/` — рабочие CSS, JS и изображения;
- `scripts/` — обновление, диагностика и перенос;
- `tests/` — автоматические проверки;
- `docs/` — подробная документация;
- `CHANGELOG.md` — история выпусков;
- `install.sh` и `bootstrap.sh` — установка и управление.

## Nexus Node — необязательный эксперимент

Основной сценарий — существующие 3x-ui/Remnawave. Агент автоматически не
устанавливается. Его раздел и API по умолчанию выключены. Таблицы и прежние
регистрации не удаляются. Для отдельного тестового стенда можно задать
`NEXUS_NODE_ENABLED=1` в окружении панели и пересоздать контейнер.
Код находится в `node-agent/`, но он пока не готов как рабочая VPN-нода:
не завершены синхронизация клиентов, надёжная доставка заданий и откат
конфигурации. Это обновление не исправляет все ограничения прототипа.
