# Nexus 2.7.25 — подписки 3x-ui и ручной Endpoint

Основа — предоставленный пользователем архив 2.7.24 от 3 ноября 2026, с AmneziaWG 3.1 / INCY. Это локально подготовленный релиз: он не опубликован в GitHub и не установлен на VPS. Кнопка обновления из публичного репозитория получит эти изменения только после их публикации.

## Что исправлено

1. Подписка больше не использует сохранённый inbound бессрочно. После устаревания минутного кэша Nexus читает полный inbound с тем же ID и обновляет порт, REALITY public key, Short ID, транспорт и XHTTP extra. Одновременные запросы одного подключения объединяются, выполняется максимум 8 refresh. При превышении лимита узел с кэшем обслуживается из кэша и будет перепроверен при следующем запросе. Каталог пользователей не начинает опрашивать удалённые API.
2. При временном сбое API сохраняются последние проверенные параметры, повторное чтение откладывается на 15 секунд. Подтверждённое отсутствие/несовпадение ID не заменяется чужим inbound. Смена API-подключения во время запроса не записывает ответ старого подключения. Это не доказывает актуальность старых ключей при недоступном API.
3. Обычный исходный Flow Vision больше не заменяется на xtls-rprx-vision-udp443. Если суффикс уже указан в источнике, включённый UDP/443 сохраняет его, выключенный возвращает обычный Vision. XHTTP не получает Vision; Mux сам не включается.
4. В REALITY VLESS-ссылке передаётся support-x25519mlkem768=true по примеру актуальной 3x-ui. В узле есть выключатель для старого REALITY. Выключатель имеет приоритет, явное false из источника сохраняется. В TLS hint не добавляется. В native Xray JSON такого поля нет; вместо фиктивного boolean сохраняется поддерживаемый mldsa65Verify/pqv. Совместимость ML-KEM по-прежнему зависит от ядра приложения.
5. Подпись активности узла говорит «API доступен». Ответ API не означает успешный VPN-handshake, доступность Endpoint с телефона или работу UDP.
6. Восстановлены отсутствовавшие в исходном ZIP скрытые .dockerignore/.gitattributes, default build network комплектного Compose. База, .env и backup не должны попадать в новый образ. Это не удаляет старые образы/кэш.

Подтверждение upstream: [3x-ui PR #6712](https://github.com/MHSanaei/3x-ui/pull/6712) описывает URI hint и исключение неподдерживаемого boolean из native Xray JSON. [Документация sing-box VLESS](https://sing-box.sagernet.org/configuration/outbound/vless/) документирует стандартный Vision Flow. Одного номера версии панели недостаточно для определения поддержки транспорта ядром клиента.

## Ручной Endpoint

Откройте **Узлы → Добавить узел** или **Узлы → нужный узел → Изменить**. Под адресом API есть поле **Endpoint в подписке (необязательно)**.

Примеры:

    vpn.example.com:10443
    192.0.2.10:26589
    [2001:db8::10]:26589

Указывается только домен/IP и порт, без https://, пути и ключей. Проверяется синтаксис и диапазон порта 1–65535. DNS/доступность не проверяются при вводе.

- Это настройка одного подключения Nexus к 3x-ui, включая VLESS, Trojan, Shadowsocks и нативный AmneziaWG.
- Ручной адрес приоритетнее адреса, рекламируемого 3x-ui/externalProxy, и замены адреса в перенаправлении. Если inbound публикует несколько ссылок, адрес/порт заменяются во всех ссылках этого узла.
- В SUB меняется адрес ссылки; в JSON — адрес/порт outbound. Для AWG меняется именно Endpoint внутри конфигурации, включая смешанный JSON INCY.
- API URL, SNI, HTTP Host, path, UUID, ключи и listener на сервере не меняются. Для TLS/REALITY сохраняйте действительное имя сервера в SNI отдельно.
- Внешний адрес/порт должен уже доставлять нужный TCP/UDP-транспорт на сервер. Поле само не создаёт переадресацию, не публикует Docker-порт и не настраивает firewall.
- Очистка поля и сохранение возвращают автоматическое определение адреса. Настройка сохраняется при перезапуске и клонировании. Старые формы без поля не стирают сохранённое значение.
- Remnawave использует настройки Hosts своей панели; этот локальный override в Remnawave не применяется.

После сохранения обновите подписку в приложении и переподключитесь. Если приложение продолжает использовать прежний импорт, сравните новый адрес в полученной конфигурации с Endpoint в Nexus.

## Установка подготовленного патча

Загрузите Nexus-Panel-2.7.25-subscription-compat-patch.zip в /root и распакуйте в отдельный каталог:

    unzip /root/Nexus-Panel-2.7.25-subscription-compat-patch.zip -d /root/nexus-update-2.7.25
    bash /root/nexus-update-2.7.25/apply-node-traffic-update.sh /opt/3xui-aggregator

Передайте фактический каталог установленной панели; он может называться /opt/3xui-aggregator-vp. Helper проверяет manifest/config, запрашивает YES, останавливает aggregator, сохраняет backup и переносит файлы с пересборкой. Внешние DATA_DIR/control/workspaces/volumes за пределами каталога сохраните отдельно заранее. Проверяйте свободное место; исключения Docker уменьшают будущий контекст, но не освобождают старые слои. Существующий Compose не заменяется комплектным шаблоном: сохраняются имена, порты и volumes, выполняются прежние узкие миграции build/Caddy.

Зависимости не изменены. В БД автоматически добавляются два столбца nodes: reality_mlkem_hint (по умолчанию 1) и subscription_endpoint (по умолчанию пусто). Клиенты, ссылки подписок и ключи не пересоздаются этой миграцией.

Для systemd: остановите сервис, сохраните согласованную копию исходников/баз, перенесите файлы из PATCH_FILES.txt с сохранением путей, выполните npm ci --omit=dev и запустите сервис. Для отката остановите сервис и восстановите исходники/базы/.env/прокси из одного backup, затем пересоберите и запустите. После успешного запуска проверьте версию 2.7.25 и обновите подписку.

Полный архив Nexus-Panel-2.7.25-source.zip предназначен для исходников/дальнейшей публикации. Не заменяйте им вслепую рабочие .env, data и Compose.

## Проверки и ограничения

Целевой набор npm run test:subscription-compat: 24/24. Локальные HTTP-запросы проверяют TCP REALITY → XHTTP REALITY после устаревания кэша, смену порта/ключа/SID, XHTTP extra, исходный Flow, pqv в JSON, отсутствие фиктивного поля JSON, объединение запросов, transient fallback, выключатель и перезапуск. Проверены ручной Endpoint в SUB/JSON VLESS и AWG, IPv6, приоритет над перенаправлением, очистка и сохранение учётных данных. Дополнительные unit-тесты проверяют недопустимые Endpoint и отказ от чужого inbound.

Headless Edge в production-фикстуре: 4/4 HTTP/UI сценария; формы и отсутствие горизонтального переполнения на 1440/390, снимки просмотрены. Это не физический iPhone. Проверены 20 EJS и синтаксис JS/Bash. Подробные итоговые результаты полного набора — в PROJECT_HANDOFF.md; полный набор имеет прежние ошибки и не объявляется полностью зелёным.

Настоящие Docker build, VPS, Xray handshake, мобильные Happ/v2rayTun/INCY/Karing и звонки WhatsApp здесь не проверялись. Не утверждается, что исчезновение URI hint — единственная причина конкретного сбоя пользователя. После установки сравните в приложении выданный узел с отдельной рабочей конфигурацией и проверьте реальное подключение.
