# Nexus 2.7.11 — маршрутизация JSON для Remnawave

15 октября 2026 года. Исправление подготовлено локально, на боевой сервер не устанавливалось; GitHub не обновлялся. Оптимизация 2.7.10 сохранена.

## Причина

В `isRoutingEnabledForNode()` был жёсткий запрет для `NODE_TYPE_REMNAWAVE`. Форма маршрутизации позволяла выбрать такой узел, но генератор JSON получал `false` и пропускал `routing`. Это ошибка Nexus, а не несовместимость Remnawave 3.3.0.

Запрет убран. Remnawave теперь следует той же логике назначений Nexus, что и 3x-ui: общее включение, выбранный для узла режим, исключения, proxy-списки, блокировки и прежние настройки «Все узлы»/исключений. Узел без назначения не получает правила другого узла. Параметры подключения VLESS/XHTTP/TLS не изменяются.

Это **клиентская** маршрутизация в `/json/<slug>` Nexus, включая JSON-массив и совместимый одиночный конфиг `?node=N`. Серверные Config Profiles Remnawave и правила выхода relay/exit не переписываются. Версию Remnawave обновлять не нужно. Если нужны именно серверные правила, это отдельная настройка в Remnawave, не результат данного исправления.

## Как включить после обновления

1. В Nexus открыть «Маршрутизация», включить её и нужный режим.
2. Отметить нужные Remnawave-узлы. Один узел назначается только одному режиму.
3. Ввести исключения/списки и сохранить.
4. В приложении обновить **JSON-подписку Nexus** (`https://домен-nexus/json/<slug>`), затем переподключиться. Для проверки сырого JSON в браузере добавить `?download=1`.
5. В конфиге выбранного Remnawave-региона должен присутствовать `routing.rules` с сохранёнными правилами. Приложение должно поддерживать полный Xray JSON и не заменять его своим глобальным режимом.

Одиночный `vless://` и список ссылок SUB не содержат блок `routing` Xray. Обновление обычного списка ссылок или прямой подписки Remnawave не загрузит правила из JSON Nexus. Отдельный Happ routing-профиль остаётся независимой опцией и этим патчем не включается.

Значение `direct` в клиентских правилах означает выход с устройства пользователя, а не с российской relay-ноды. В режиме proxy-except исключения идут direct, остальное через выбранный узел; в node-selective выбранные назначения идут через узел, остальное direct. Блокирующие правила имеют прежний приоритет.

## Установка

Накопительный архив для существующей Nexus 2.7.7–2.7.10, включая предыдущие исправления. Устанавливать **только на сервер Nexus**, не на Remnawave и не на ноды. Публичная команда обновления и `panel-script-v1.sh --update` этот локальный архив не устанавливают.

Сохранить резервную копию всех баз и настроек; внешние DATA_DIR/control/workspaces/volumes скопировать отдельно. Для стандартного Docker-развёртывания загрузить ZIP на сервер и выполнить:

```bash
unzip Nexus-Panel-2.7.11-remnawave-routing-patch.zip -d /root/nexus-routing-2.7.11
cd /root/nexus-routing-2.7.11
bash apply-node-traffic-update.sh /opt/3xui-aggregator
```

Указать реальный каталог существующего Nexus вместо `/opt/3xui-aggregator`. Helper требует YES, останавливает только `aggregator`, сохраняет весь каталог рядом в backup, накладывает manifest и пересобирает этот сервис. Внешние данные он автоматически не копирует. Пользователи, пароли, ноды и правила не удаляются.

Для systemd: остановить свой сервис Nexus, сохранить исходники, настройки и базы, наложить PATCH_FILES.txt с сохранением путей, выполнить `npm ci --omit=dev`, запустить сервис. Откат — остановка Nexus и восстановление исходников и баз из полной копии, не замена базы работающего процесса. Удалённые действия квот/сквадов восстановление локальной базы само не отменяет.

## Проверки

- До исправления три новых теста воспроизвели отказ Remnawave, после — прошли. Проверены основные и старые имена типа Remnawave, назначения, исключения, старый all-nodes режим и общее отключение.
- Настоящий HTTP-тест с фикстурной Remnawave 3.3.0: сохранение формы, выдача двух регионов с разными режимами, direct/proxy/block правила, одиночный JSON, снятие назначения и выключение маршрутизации. Сохранены VLESS UUID, адреса, XHTTP host/path/mode/padding и TLS; серверный API в тесте не поддерживает изменения Config Profiles.
- Целевой набор: 27/27 (маршрутизация, HTTP-квоты/сбросы, изоляция Remnawave Host, транспорт XHTTP и оптимизация). Синтаксис JS и все 20 EJS-шаблонов проверены. Проверки в реальном приложении на телефоне и на сервере пользователя не выполнялись.
- Полный исторический набор по-прежнему имеет прежние падения; их список и результаты текущего прогона — в PROJECT_HANDOFF.md. Не считать весь набор зелёным.
