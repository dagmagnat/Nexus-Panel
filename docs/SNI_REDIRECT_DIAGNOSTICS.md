# SNI, ручной redirect IP и диагностика

## SNI-профили

В настройках панели появился блок **SNI-профили REALITY**. В нём можно сохранить часто используемые SNI, например `m.vk.com`, `web.max.ru`, `browser.yandex.ru`, и проверить их TLS-доступность.

Проверка SNI делает:

- DNS resolve домена;
- TCP/TLS connect на 443;
- handshake с `servername = SNI`;
- вывод subject/issuer/validTo сертификата и задержки.

Это не гарантирует качество REALITY-соединения, но помогает быстро отсеять несуществующие или недоступные SNI.

## SNI на узле

В карточке редактирования узла добавлен режим **SNI в подписках**:

- **Из 3x-ui inbound** — используется SNI, который подтянут из удалённой 3x-ui панели;
- **SNI-профиль** — используется сохранённый профиль из настроек;
- **Ручной ввод** — используется SNI, введённый прямо в узле.

Это меняет только выдаваемую подписку. Inbound на 3x-ui меняется только если включить отдельную галочку сохранения inbound-параметров в 3x-ui.

## Ручной IP редиректа

В разделе **Перенаправление** теперь можно выбрать:

- IP панели / найденный IP;
- свой IP редирект-сервера.

Если выбран свой IP, в подписке меняется только адрес узла. Порт остаётся портом оригинального inbound. Это подходит для схемы, где на отдельном сервере уже настроен DNAT/forwarder на тот же порт.

## Диагностика узла

В разделе **Диагностика** добавлен блок **Проверка узла: напрямую / через редирект**. Он показывает:

- TCP-доступность оригинального узла;
- TCP-доступность активного redirect IP;
- TLS/SNI-проверку;
- предупреждения по REALITY, XHTTP и flow.

Проверка не является полноценным VPN-клиентом, но помогает понять, где ломается маршрут: прямой узел, входной redirect IP или SNI.
