# Nexus 2.7.14 — служебный узел после окончания подписки

15 октября 2026. Локальный накопительный патч. На сервер пользователя не установлен, GitHub не обновлён. Предыдущая оптимизация, Remnawave routing, изолированные служебные аккаунты и несколько автоподключений включены.

## Что установлено проверкой

1. Для недавно истёкшего клиента стандартный режим 7 дней выдаёт уведомление, а затем реальный служебный узел в обоих форматах — JSON и SUB.
2. Стандартные 3/7 дней считались **от даты окончания основной подписки**, не от добавления узла. Клиент, истёкший 30 дней назад, получал только уведомление. Учётная запись на узле могла успешно создаться выключенной; «ошибок клиентов: 0» отражало успешную синхронизацию, а не право доступа. Это воспроизводит описанный симптом, но дата окончания тестового клиента на production не предоставлена; точная причина на сервере пользователя не подтверждена.
3. Найдено несовпадение дат: уведомление нормализовало секунды/миллисекунды, а supportAccess использовал сырое число. Исправлена нормализация основного срока и индивидуальных grant-дат. База/основной срок не переписываются.

## Как включить нужное поведение

1. Обновить Nexus этим архивом.
2. В настройках подписки открыть блок про истёкшие подписки. В «Служебный доступ после окончания» выбрать **«До продления основной подписки»**, убедиться, что выбран узел «Telegram для связи», сохранить.
3. Если клиенту ранее назначались индивидуальные 3/7/другие дни: Пользователи → выбрать клиента → Применить к выбранным → Служебный доступ → вернуть общие настройки либо назначить бессрочный служебный доступ. Индивидуальный срок имеет приоритет над общим.
4. Обновить прежнюю SUB или JSON-ссылку **Nexus** в приложении. Для истёкшего клиента сначала будет уведомление о продлении, затем выбранный служебный узел. Прямая ссылка 3x-ui не получает правила выдачи Nexus.
5. В редакторе клиента посмотреть блок «Служебный»: отдельная причина (основная подписка действует / служебный срок закончился / клиент отключён / узел выключен) и статус фоновой синхронизации. Если есть ошибка — устранить её, а не выключать защиту общей учётной записи.

Прежние 3/7 дней **сохраняются**: обновление не делает всем бессрочный доступ автоматически. Общий вариант 0 теперь означает «до продления основной подписки» и поддерживается сохранением/чтением, preferences и переносом настроек. Пока основной срок не закончился, служебный аккаунт выключен и скрыт. После продления снова скрывается и выключается. Отключённым администратором и ожидающим активации клиентам доступ не открывается. Основной VPN/его лимит не продлеваются.

Служебный узел нужно ограничить серверной маршрутизацией «только Telegram»; это обновление не меняет правила Xray и не умеет надёжно отделять текст от видео Telegram. Несовместимый транспорт, неверный адрес/inbound, недоступный API и ошибка клиента не исправляются сменой срока.

## Установка

Для существующей Nexus 2.7.7–2.7.13. Сделать полную копию исходников/настроек/всех баз, включая внешние DATA_DIR/control/workspaces/volumes. На **сервере Nexus**, не на нодах:

```bash
unzip Nexus-Panel-2.7.14-expired-contact-access-patch.zip -d /root/nexus-expiry-2.7.14
cd /root/nexus-expiry-2.7.14
bash apply-node-traffic-update.sh /opt/3xui-aggregator
```

Заменить `/opt/3xui-aggregator` реальным каталогом установки. Helper требует YES, останавливает только aggregator, сохраняет весь каталог в backup рядом и пересобирает этот сервис. Внешние данные он автоматически не копирует. Для systemd: остановить сервис, сохранить полную копию, наложить PATCH_FILES.txt с путями, `npm ci --omit=dev`, запустить. Откат — остановить сервис и восстановить исходники/базы из полной копии; локальный откат не отменит удалённые операции 3x-ui.

Публичный updater и `panel-script-v1.sh --update` этот неопубликованный ZIP не устанавливают. Предыдущие ZIP отдельно устанавливать не требуется.

## Проверки

Настоящая Nexus и фикстурные legacy/password и global v3/token 3x-ui, основной и отдельный служебный inbound в общей панели. Для истёкших 1 и 30 дней: фоновое создание, воспроизведение «нулевые ошибки + только уведомление» при закончившемся finite окне, сохранение режима 0 через настоящий HTTP settings handler, уведомление + служебный config в JSON/SUB, отсутствие истёкшего общего лимита/expire в служебном режиме, восстановление выключенного mapping при обновлении, выключение/скрытие после продления и стабильный UUID после перезапуска. Платные UUID/срок/лимит не меняются. Ошибочная лишняя привязка v3 блокирует глобальное включение; исправление допускает повтор. Unit: секунды/миллисекунды, причины, индивидуальный приоритет, disabled/pending, preferences value 0.

Это локальные проверки, не подключение к production и не проверка Telegram на телефоне.

Целевой release-набор: 55 pass, 4 platform skip, 0 fail. Полный исторический набор: 204 pass, 9 прежних fail, 16 skip; он не зелёный, категории указаны в PROJECT_HANDOFF.md. JS/module, 20 EJS и bash-синтаксис helper проверены.
