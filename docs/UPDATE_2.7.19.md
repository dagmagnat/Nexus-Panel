# Nexus Panel 2.7.19 — назначение узлов отдельным пользователям

## Что исправлено

В **Пользователи → Редактировать → Узлы клиента** снова показаны все включённые узлы 3x-ui и Remnawave текущего рабочего пространства. Узел, добавленный без импорта/создания пользователей, сразу доступен без галочки. Чтобы выдать тестовый доступ, отметьте его у нужного человека, при необходимости укажите ГБ и нажмите **Сохранить изменения**. Создаётся или привязывается только этот клиент на выбранном узле; массово добавлять остальных не требуется.

Уже назначенные узлы сохраняют галочки и лимиты. Отключённые только у клиента узлы видны без галочки и могут быть включены снова. Глобально отключённые узлы скрыты, их сохранённые привязки не переписываются. Включённый, но недоступный узел остаётся в списке: при ошибке удалённого API Nexus сообщает, что изменения приняты не всеми узлами; это не означает успешное создание на недоступном сервере.

Для одинаковых названий показаны ID узла и inbound (для Remnawave — тип Internal Squad). Автоподключения не являются отдельными физическими узлами и в этот список не добавляются.

ГБ: число — лимит узла, `0` — безлимит на уровне настройки узла, пустое поле — наследование общего лимита клиента. Не менялись глобальные ограничения клиента и ограничения удалённых панелей. В одной Remnawave-панели пользователь и его квота по-прежнему общие: исправление списка не превращает Squads в независимых удалённых пользователей.

Причина: оптимизированная выборка трафика возвращает только реальные привязки пользователя, и редактор ошибочно использовал её как полный каталог узлов. Теперь редактор объединяет уже загруженный каталог включённых узлов с привязками. Статистика остаётся по реальным связям; дополнительных запросов в БД или к удалённым панелям при открытии страницы нет. Серверный обработчик создания/привязки не заменялся.

## Установка на сервер Nexus

Это локальный накопительный патч для Nexus 2.7.7–2.7.18 с поддержкой рабочих пространств. Он не опубликован на GitHub и не установлен на ваши серверы автоматически. Не устанавливайте его на CDN/relay/exit-ноды вместо сервера Nexus.

Сначала сохраните полную копию Nexus, `.env` и баз. Внешние `DATA_DIR`, control/workspace-каталоги и Docker volumes сохраните отдельно: helper архивирует каталог установки, не весь VPS.

```bash
unzip Nexus-Panel-2.7.19-client-node-editor-patch.zip -d /root/nexus-update-2.7.19
bash /root/nexus-update-2.7.19/apply-node-traffic-update.sh /opt/3xui-aggregator-vp
```

Подставьте фактический каталог Nexus. После проверок helper запросит `YES`, остановит aggregator, сохранит backup и пересоберёт приложение. Старое имя каталога допустимо: оно не является ошибкой и не требует переноса.

Сохранены [переключатель ссылок 2.7.18](UPDATE_2.7.18.md) и [миграция установки 2.7.17](UPDATE_2.7.17.md). Существующий Compose не заменяется целиком; известный `build.network: host` меняется на `default`, ограниченный Caddy-шаблон дополняется чистыми маршрутами. При изменении Caddy его контейнер проверяется и пересоздаётся, возможен краткий перерыв. Нужен `python3`. Небезопасный ADMIN_PASSWORD отклоняется до остановки; пароль администратора в БД не сбрасывается. Произвольный внешний прокси автоматически не редактируется.

После установки:

```bash
cd /opt/3xui-aggregator-vp
docker compose ps
docker compose logs --no-color --tail=60 aggregator
```

Через 20–30 секунд убедитесь, что контейнер остаётся Up. Откройте редактор тестового пользователя, отметьте новый узел, сохраните и проверьте его на удалённой панели и в обновлённой подписке. У других клиентов новый узел должен оставаться неназначенным. Существующие подписки/клиентов не удаляйте.

Для systemd: остановить сервис, сохранить согласованную копию исходников/баз, перенести файлы из `PATCH_FILES.txt` с сохранением путей, выполнить `npm ci --omit=dev` и запустить сервис. Для отката остановить сервис, восстановить исходники/базы/.env/прокси из одного backup, пересобрать и запустить. Откат только интерфейса не удаляет уже созданного удалённого клиента.

## Проверки

Настоящие локальные HTTP-запросы к Nexus с mock API legacy/modern 3x-ui и Remnawave: добавление узла без импорта, каталог на разных страницах пользователей, пустые/существующие привязки, выбор только одного клиента, переиспользование UUID, повторное сохранение без дубля, дробные/нулевые/наследуемые ГБ, снятие галочки, сохранение скрытых привязок, CSRF, отказ отрицательного лимита, перезапуск. В тестах отдельно проверено отсутствие удалённых запросов при открытии списка.

Локальный headless Edge, приложение в production-режиме: выбор, массовые кнопки формы и сохранение на ширинах 1440/390, без ошибок JavaScript и горизонтального переполнения. Снимки просмотрены. Это не проверка на физическом телефоне или реальных 3x-ui/Remnawave-серверах. Linux/Docker/Caddy production не проверялись.

Целевой набор: 44 теста, 36 pass, 8 platform skip, 0 fail. Четыре новые HTTP-регрессии проходят; до исправления все четыре воспроизводили отсутствие нового узла. UI-прогон этих же четырёх фикстур с Edge также 4/4. Проверены JS, 20 EJS и Bash-синтаксис установщика/helper.

Полный набор: 256 тестов, 230 pass, 9 прежних fail, 17 platform skip. Названия падающих тестов совпадают с 2.7.18 (Python PATH ×3, VM budget, устаревшие ожидания inbound/CSS/grace/device-grace/RBAC); полный набор не зелёный, эти проблемы не объявлены исправленными. Локальные журналы `work/client-node-editor-*.log` в ZIP не входят.
