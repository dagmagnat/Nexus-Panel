# Nexus 2.7.29 — автовыбор, массовые действия и квоты

## Что изменилось

### Автовыбор

- Интервал фоновых HTTPS-проверок по умолчанию — 5 секунд вместо 30. Существующее значение 30 секунд один раз меняется на 5 при запуске обновлённой панели; остальные значения сохраняются. Если позже вручную выбрать 30, повторный запуск его не изменит.
- В обычном пуле появился отключаемый «Быстрый старт»: пока Xray ещё не получил здоровый результат, он может попытаться использовать первый основной узел. Этот fallback также действует, когда все проверки неуспешны. Он не объявляет узел исправным и не гарантирует соединение. Снимите галочку, если требуется строго блокировать соединения до положительной проверки.
- Для профилей с приоритетным или аварийным узлом эта опция не меняет существующую цепочку переключения. Проверки остаются параллельными: параллельность была и в предыдущей версии.
- Это проверка HTTP(S)-запросом через каждый выход, а не только TCP-пинг. Обычный observatory Xray не гарантирует именно код 204 и не проверяет все приложения/сайты. Интервал 5 секунд — пауза между циклами, а не обещание подключения за 5 секунд: неудачная проверка в изученном Xray имеет собственный тайм-аут около 5 секунд.

Чтобы ограниченные LTE-узлы были запасными, создайте один профиль: обычные серверы в основном пуле, один ограниченный — аварийным. Отдельные профили Wi-Fi и LTE автоматически друг в друга не переходят. После восстановления основного пула новые соединения снова выбирают основной; уже открытые видеозвонки/потоки через запасной узел могут продолжаться до завершения или переподключения. Это не ограничитель суммы трафика аварийного узла.

Причина части задержек подтверждена: прежний обычный пул блокировал запросы до первого положительного результата observatory. Старый 30-секундный интервал также увеличивал ожидание повторной проверки. Измерение локальным официальным Xray 26.10.21 с реальными выходами показало первоначальный неудачный запрос без быстрого старта и успешный первый запрос с ним; это не замер на iPhone и не доказательство причины любого долгого подключения. DNS, правила, доступность сервера, клиентское ядро и сеть тоже влияют.

### Массовые действия

В «Пользователи» добавлена отдельная форма выбора области: все клиенты, группа или метка. Она работает по всей базе независимо от страницы, числа строк и текущего поиска. Можно выбрать узел, назначить лимит ГБ/IP, сбросить расход либо удалить клиентов из выбранного узла. Пустые поля лимитов сохраняют текущие значения; 0 ГБ — безлимит. Перед действием требуется подтверждение.

В списке узлов на ПК и телефоне, а также в редакторе есть «Удалить всех клиентов из узла». Удаляются назначенные этому подключению клиенты, которыми управляет Nexus. Пользователи в Nexus и их доступ к другим узлам сохраняются. Посторонние аккаунты удалённой панели, не связанные с Nexus, эта кнопка не удаляет. Используется существующая операция удаления с проверкой CSRF/прав/пространства, ходом выполнения и учётом ошибок API. У нового Clients API 3x-ui снимается выбранная привязка, а не весь общий аккаунт.

### Обновление квоты

В «Настройки → Подписки → Устройства и блокировки» добавлен период восстановления квоты: каждые 30 дней либо выключено. По умолчанию — 30 дней. Обнуляется расход, сам лимит сохраняется: при квоте 10 ГБ после сброса снова доступны 10 ГБ, остаток не суммируется. Срок подписки не продлевается.

- Первый период начинается, когда фоновая задача впервые видит ограниченную привязку после обновления или назначения квоты. Проверка запускается через 15 секунд после старта, затем раз в минуту. Сроки сохранены в БД и переживают перезапуск. Изменение размера квоты и ручной сброс не переносят дату этого периода. После выключения и повторного включения настройки начинается новый 30-дневный период.
- После длительного простоя выполняется один сброс, без многократного обнуления за пропущенные месяцы. Новый период начинается с успешного сброса.
- Отключённые/истёкшие/ожидающие активации пользователи и выключенные узлы не получают продление или автоматическое включение. Ручное отключение привязки сохраняется.
- Для Remnawave обновляется независимый счётчик узла в Nexus и пересчитывается доступ; общий удалённый расход пользователя не обнуляется. Для 3x-ui используется поддерживаемый API сброса. У современного 3x-ui общий аккаунт сбрасывается один раз для всех его привязок; нативный общий счётчик не становится независимым на каждом inbound.
- Для персональных AWG обновляется суммарный счётчик владельца и пересчитываются квоты устройств.
- Ошибка API отображается в настройках, операция повторяется. После подтверждённого сброса восстановление доступа повторяется отдельно без нового обнуления. Как у любой удалённой операции, потеря ответа после выполнения сброса не позволяет абсолютно точно установить результат без подтверждения сервера.

### Интерфейс

Удаление в карточке узла больше не наследует левый отступ и вертикальный разделитель формы редактора. Кнопка выровнена по сетке с соседними действиями.

## Установка

Архив содержит только новые/изменённые файлы относительно 2.7.26. Подходит поверх 2.7.26, 2.7.27 или 2.7.28; включает предыдущие исправления Vision и устройств AWG. Не является установкой на чистый сервер.

Распакуйте в отдельный каталог и выполните:

```bash
cd /root/nexus-2.7.29
sudo bash apply-autoselect-update.sh /opt/3xui-aggregator
```

Последний путь замените на реальный каталог установленной Nexus с `.env` и `docker-compose.yml`. Используйте именно `apply-autoselect-update.sh`, а не helper предыдущей версии. Скрипт запрашивает YES, останавливает aggregator для резервной копии каталога установки в соседнюю `.nexus-backups`, возвращает старый контейнер на время сборки, затем запускает новый. Внешние каталоги данных/volumes резервируются отдельно. Архив не заменяет Compose, Caddy, `.env` или рабочую БД; схема и новые параметры мигрируют при запуске приложения.

После обновления проверьте настройку 30-дневной квоты. Для изменения клиентского автовыбора обновите подписку в приложении и переподключитесь. Уже импортированный старый JSON сам по себе не меняется.

## Проверки и ограничения

Целевые проверки: 57/57. Финальный полный набор: 290 тестов, 261 успешный, 19 пропущено, 10 прежних ошибок (имена совпадают с 2.7.28). Сам факт этих прежних ошибок не скрывается; общий набор не объявляется полностью зелёным.

- Модульные проверки периодов: 30 дней, перезапуск, ошибка API, единичный сброс общего аккаунта, пропущенные периоды и восстановление доступа без повторного сброса.
- HTTP-проверки: настоящая фоновая задача обнуляет просроченную квоту через mock legacy/modern 3x-ui API; массовые действия по всей базе/группе/метке/узлу, сохранение других пользователей и привязок. Серверный выбор проверен на 2100 пользователях за пределами одной страницы.
- Проверки нескольких профилей, строгого/быстрого старта, аварийной цепочки, одноразовой миграции и сохранения выбора после перезапуска.
- Edge/Playwright: 1440 и 390 пикселей, формы и выравнивание кнопки, отсутствие горизонтального переполнения. JS и все 20 EJS-шаблонов компилируются.
- Данные и клиенты на рабочих VPS в процессе разработки не менялись. Сам Happ/INCY на физических телефонах не проверен; проверена генерация Xray JSON и ограниченное исполнение официальным Xray. Старые ошибки общего набора тестов перечислены в журнале продолжения и не считаются исправленными этим патчем.

Первичные источники по поведению Xray: [Observatory](https://xtls.github.io/en/config/observatory.html), [реализация observer.go v26.10.21](https://github.com/XTLS/Xray-core/blob/v26.10.21/app/observatory/observer.go).
