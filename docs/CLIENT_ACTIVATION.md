# Срок с первой активации устройства

При создании или редактировании клиента доступна галочка «Начать после активации».
По умолчанию она снята: прежний расчёт срока от создания сохраняется.

Чтобы выдать тест на три дня, укажите срок 3 и включите галочку. До первого
добавления подписки в приложение клиент отображается как «Ждёт активации»,
дата окончания отсутствует, учётная запись на назначенных узлах отключена.
Копирование ссылки, страница /open и запрос из браузера срок не запускают.

Первый GET подписки с допустимым заголовком `x-hwid`, принятый реестром устройств,
привязывает устройство и фиксирует время активации. Три дня означают ровно
72 часа от этого момента, даже если ссылку выдали неделю назад. Отсчёт начинается
при импорте/обновлении подписки приложением, не при первом VPN-пакете.
HWID — идентификатор, сообщаемый приложением; это не аппаратная аттестация.
Приложение без HWID получит уведомление об активации вместо рабочего доступа.
Ссылка отдельного сервера VLESS не запускает активацию: используйте SUB/JSON
подписку Nexus Panel.

Сохранённая дата едина для всех узлов. Повторные запросы, перезапуск панели,
добавление или удаление устройств не перезапускают период. При недоступном узле
синхронизация остаётся в базе и повторяется при запросе подписки и фоново каждые
30 секунд с той же датой окончания. До подтверждения синхронизации приложение
получает HTTP 503 с Retry-After; повторите обновление подписки.

В редакторе ожидающего клиента можно изменить число дней; ожидание сохранится.
Снятие галочки запускает ожидающий период сразу. Продление ожидающего клиента
добавляет дни к будущему периоду. Для 0 дней (бессрочно) галочка не применяется.
Клиента, у которого уже была активация, устройство или запись об использовании,
нельзя заново поставить на первый старт. Для нового теста создайте нового клиента.

Миграция добавляет поля `start_on_activation`, `activation_started_at` и
`activation_sync_pending`. Существующие записи получают нули, UUID и sub_slug
сохраняются. Полный backup и перенос клиентов сохраняют эти поля; перенос
отложенного клиента в старую схему базы отклоняется с просьбой обновить панель.

## Проверки

`node --test tests/client-activation.test.js` — 7 сценариев на SQLite:
создание обычного/ожидающего клиента, 72 часа, параллельные обновления, браузер,
HEAD, HWID, запрет активации отключённого клиента, сбой узла и повтор,
редактирование, отсутствие повторного запуска после сброса устройств.
Сетевые API узлов в этих тестах заменены тестовыми адаптерами.
Полный HTTP/EJS-прогон и проверка на реальных 3x-ui/Remnawave в этой среде
не выполнялись: зависимости панели не установлены.
