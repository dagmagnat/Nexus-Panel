# Nexus 2.7.8 — раздельный расход и сброс по узлам

## Что изменено

- Главная → **Трафик** открывает отдельную страницу узлов. Нажмите узел: увидите клиентов и расход именно на нём.
- Периоды: сегодня, 3, 7, 30 дней или две произвольные календарные даты включительно. Дни UTC, до 370 дней в запросе. ГБ = 1024³ байт.
- «За период» — исторический расход. «Счётчик лимита» — расход после последнего сброса. Это разные показатели.
- Пользователи → выбрать клиентов → Действия → Сбросить трафик → выбрать узел или все узлы. «Выбрать все» относится к текущему поиску/фильтру.
- В окне «Лимиты узлов» показываются все назначенные узлы, включая безлимитные; у каждой строки есть сброс.
- Один узел Remnawave сбрасывается через независимую базовую отметку Nexus. Общий счётчик удалённого пользователя не меняется. История не стирается.
- Явный массовый сброс «Все узлы» сбрасывает все выбранные привязки и общий пользовательский счётчик каждой Remnawave-панели один раз. XUI использует свой обычный сброс выбранного inbound.
- Сбор работает в фоне примерно раз в минуту и не требует открытой страницы. Ограничение не является мгновенным: задержка включает обновление статистики Remnawave и опрос Nexus.

## Настройка Remnawave: важно

Для каждого физического сервера:

1. В Remnawave создайте отдельный Internal Squad, который даёт доступ **только к этому физическому серверу**. Разные названия сквадов сами по себе недостаточны: проверьте их доступные ноды/inbound.
2. В Nexus → Узлы → редактор укажите API панели, этот **Internal Squad UUID**, **UUID физической ноды** и нужный **Host UUID** для фильтрации клиентских ссылок. Если сквад доступен ровно одной ноде, физический UUID определяется автоматически.
3. У пользователя задайте ГБ в строках соответствующих узлов. Если нужен только раздельный лимит, общий лимит клиента поставьте **0 — без лимита**. Ненулевой общий лимит дополнительно ограничивает общую учётную запись Remnawave.
4. Откройте Трафик → «Обновить с узлов». Проверьте UUID, API-версию и отсутствие предупреждений.

Когда квота ноды исчерпана, Nexus убирает только её эксклюзивный сквад у пользователя. При сбросе восстанавливает его, если пользователь, назначение и узел включены, срок не истёк и активация состоялась. Чужие сквады сохраняются. Общий сквад нескольких нод не отключается: вместо этого показывается предупреждение; независимое серверное ограничение в таком случае невозможно. Локальная фильтрация подписки не заменяет серверное отключение уже выданного доступа.

Физическая нода — сервер, на котором учтён трафик конкретного пользователя, а не страна внешнего IP. Для каскада обычно это входная нода с клиентским inbound: выходной bridge может использовать другую служебную учётную запись. Два CDN-метода на одной физической ноде с одним пользователем нельзя разделить этим API: используйте одну запись сервера или отдельные удалённые учётные записи и отдельную схему учёта. Nexus предупреждает о повторном физическом UUID.

## Почему раньше расход повторялся

Nexus брал `userTraffic.usedTrafficBytes` — общий счётчик пользователя Remnawave — и сохранял его у каждого добавленного узла. Теперь источник — дневные серии `GET /api/bandwidth-stats/users/{numericId}` и UUID физической ноды. Ни импорт, ни синхронизация, ни выдача подписки не подменяют этот расход общим счётчиком.

При первом запуске старые известные неверные значения `client_nodes` архивируются в `node_usage_legacy_archive`. Старые Remnawave-снимки клиента/ноды перемещаются в `node_usage_legacy_client_traffic_snapshots` и `node_usage_legacy_node_traffic_snapshots`, чтобы первый корректный счётчик не выглядел как скачок трафика. Снимки XUI не меняются. До первого успешного сбора выводится предупреждение. Новая история хранится в `node_usage_daily`, отметки сброса — в `node_usage_state`. Архивы, базы и клиенты не удаляются. Новый экран и календарный отчёт по Remnawave используют новый источник; старый общий график со снимками до обновления может содержать ранее ошибочные данные.

Начальный независимый счётчик включает доступную историю Remnawave (запрашиваются последние 370 дней), а не угадывает прошлый момент общего сброса. Если нужно начать новую квоту с момента перехода, выполните явный сброс выбранным клиентам после первого сбора. Более старый расход и историю, которую удалённая панель уже не хранит, восстановить невозможно. Для XUI история нового экрана начинается с двух последовательных опросов Nexus. При ошибке API последние значения сохраняются; нулевой расход не подставляется вместо ошибки.

## Версии и совместимость

Сопоставлены официальные контракты Remnawave backend **3.3.0, 3.3.1, 3.3.2, 3.4.0, 3.4.1, 3.4.2, 3.4.3, 3.4.4**: файл node-scoped статистики одинаков во всех этих тегах (SHA-256 начинается `4e2cbcde8c78f516`). Между ними нет нужного здесь переключателя. Поэтому режим автоматический: Nexus читает `/api/system/metadata` и проверяет фактическую форму ответа статистики. API-версия видна у узла. Версия контейнера Node не заменяет версию backend.

Будущая версия с тем же контрактом работает без ручного выбора. Если контракт поменяется, выводится конкретная ошибка и сохраняются последние значения; возврата к общему счётчику нет. Не обещается совместимость с ещё не выпущенной 3.8 или любой будущей несовместимой версией. До 3.3 отдельная совместимость этой функции не проверена. Отсутствие metadata само по себе не блокирует корректный API статистики.

Официальные источники:

- [Контракт статистики 3.3.0](https://github.com/remnawave/backend/blob/3.3.0/libs/contract/commands/bandwidth-stats/users/get-stats-user-usage.command.ts).
- [Тот же контракт 3.4.4](https://github.com/remnawave/backend/blob/3.4.4/libs/contract/commands/bandwidth-stats/users/get-stats-user-usage.command.ts).
- [Контракт доступных нод сквада](https://github.com/remnawave/backend/blob/3.4.4/libs/contract/commands/internal-squads/get-internal-squad-accessible-nodes.command.ts).
- [Официальные релизы](https://github.com/remnawave/backend/releases) — на дату проверки 05.10.2026 последний backend 3.4.4.

## Установка архива изменений

Это локальный патч рабочей Nexus 2.7.7, не переустановка нод/CDN. Выполняется **только на сервере Nexus**. GitHub автоматически этим архивом не обновлялся. `agg update` может скачать другую публичную версию и перезаписать локальный патч.

Загрузите `Nexus-Panel-2.7.8-node-traffic-patch.zip` на сервер. Для стандартного Docker-развёртывания:

```bash
unzip Nexus-Panel-2.7.8-node-traffic-patch.zip -d /root/nexus-traffic-2.7.8
cd /root/nexus-traffic-2.7.8
bash apply-node-traffic-update.sh /opt/3xui-aggregator
```

Если Nexus находится в другом каталоге, передайте именно его. Помощник требует существующий проект Nexus и сервис Compose `aggregator`, останавливает его, сохраняет весь каталог приложения с `.env` и базами рядом в датированную резервную копию, накладывает только перечисленные файлы и пересобирает сервис. Остальные панели и ноды не меняются. Миграция при первом старте; до боевого применения рекомендуется проверить копию данных.

Если `DATA_DIR`, control/workspaces или Docker volumes вынесены за каталог приложения, сохраните их отдельно до обновления: helper не угадывает внешние пути и не включает их в архив каталога.

Для systemd/другого развёртывания: остановите **только Nexus**, сохраните весь каталог (включая `.env`, данные и control/workspaces), скопируйте файлы из `PATCH_FILES.txt` с сохранением путей, выполните `npm ci --omit=dev`, затем запустите свой сервис. Помощник для такой установки намеренно не выбирает сервис за вас.

Откат Docker: остановить `aggregator`, восстановить исходники **и базы** из полной резервной копии, затем пересобрать. Не копируйте старую базу поверх работающего процесса. Сбросы на удалённых XUI/Remnawave-панелях резервной копией Nexus не отменяются.
