# Nexus 2.7.26 — синхронизация inbound и выбор API-сервера

Продолжение 2.7.25. Все предыдущие изменения сохранены. Релиз подготовлен локально, на VPS не установлен и в GitHub не опубликован.

## Причины обнаруженного расхождения

Ручной VPN Endpoint меняет адрес, выдаваемый клиенту. Он не выбирает сервер, к которому Nexus обращается за конфигурацией по API. Если один домен имеет несколько A-записей, а на серверах стоят разные панели 3x-ui, запросы к API могут попадать в разные панели с одинаковым Inbound ID, но разными портами, ключами и параметрами AWG. Поэтому нельзя считать, что HTTP 200 подтверждает правильность выбранного сервера.

В реальной выдаче также были обнаружены RandomTrailers = true и DisableCookies = true. Это была ошибка генератора Nexus и прежнего unit-теста. В исправлении выдаётся on/off. [Официальный парсер amneziawg-tools](https://github.com/amnezia-vpn/amneziawg-tools/blob/master/src/config.c) принимает on/off или числа; true/false не поддерживает.

Два профиля AWG с одним Endpoint и разными параметрами не становятся взаимозаменяемыми: необходимо выбрать правильную API-панель и нужный inbound для каждого. Новый редактор предупреждает о повторяющихся ручных Endpoint. Автоматически удалять профили или менять ключи он не будет.

## Как закрепить API на нужном сервере

В добавлении/редакторе 3x-ui появился **IP сервера для API (необязательно)**.

- Оставьте URL панели доменным, включая правильный HTTPS-порт и Panel Path.
- Укажите IP именно той машины, на которой находится выбранная панель. Порт берётся из API URL, не из VPN Endpoint.
- Можно нажать **Взять IP из Endpoint**, если Endpoint содержит IP и панель находится на этой же машине. При внешнем relay/CDN укажите IP панели отдельно.
- API соединяется с выбранным IP, сохраняя исходный домен в URL, Host и TLS SNI. Проверка сертификата остаётся включённой. Переходы HTTP при закреплённом IP запрещены.
- Для Endpoint и API используются разные порты и настройки. Endpoint остаётся клиентским адресом подключения.
- Пустой API IP возвращает обычный DNS. IPv6 вводится без порта; квадратные скобки необязательны.

В обсуждавшемся случае: API IP — 2.27.40.95, VPN Endpoint — 2.27.40.95:50669. Сохраните узел: Nexus сразу загрузит параметры через закреплённый API. Затем нажмите **Загрузить и проверить параметры из 3x-ui**, обновите подписку приложения и переподключитесь к правильному AWG-профилю.

Изменённые адреса/API IP/Endpoint сначала сохраните. Кнопка синхронизации работает с сохранённым подключением. Не используйте для разных независимых панелей один домен без IP-привязки, если он разрешается в адреса всех этих машин.

## Автоматическая синхронизация

При добавлении/сохранении узла проверяется полный выбранный inbound. При открытии редактора Nexus снова читает выбранный inbound, проверяет ID, структуру и локальную публикацию порта. Для Xray также перечитываются Mux/FinalMask исходной панели. Неудачное чтение этих дополнительных настроек сохраняет прежние значения с отметкой ошибки.

Кнопка сверху принудительно читает выбранный inbound и обновляет кэш, не изменяя API URL, API IP, ручной Endpoint, SNI-профиль или клиентов. Она защищена CSRF и разрешением nodes.manage. Во время выдачи подписки продолжает работать минутная перепроверка с объединением параллельных запросов из 2.7.25.

Если API недоступен, редактор показывает сохранённую копию с предупреждением и временем последней загрузки. Подтверждённо чужой/удалённый inbound не подставляется вместо выбранного. Изменение подключения во время запроса не позволяет записать ответ прежнего сервера.

Загрузка из 3x-ui направлена в Nexus. Для обычного Xray обратная запись по-прежнему выполняется только с явной галочкой применения. В нативном AWG серверные параметры меняются в 3x-ui и автоматически перечитываются Nexus: Xray RAW/Sniffing/full-JSON в AWG не записываются.

## AmneziaWG

Редактор показывает UDP и реальные параметры AWG, не RAW/NONE. Не отображаются неприменимые Sniffing, REALITY, Mux/Fragment/Noises и Xray-настройки транспорта. Серверный private key и HeaderProtectionKey не выводятся в сводке; значения I1–I5 сокращены до признака наличия и длины.

Проверяются серверный public key, формат HeaderProtectionKey, диапазоны H1–H4, J/S, таймеров, порядок Jmin/Jmax и boolean-поля. Клиентские PrivateKey/Address берутся только из нужного inbound. В SUB и JSON INCY сохраняются остальные параметры и ручной Endpoint.

Проверка API/формата не доказывает, что на VPS запущен UDP listener, разрешён firewall или работает handshake с конкретным приложением. API 3x-ui не заменяет проверку сокета на сервере.

## Установка

Загрузите патч в /root:

    unzip /root/Nexus-Panel-2.7.26-parameter-sync-patch.zip -d /root/nexus-update-2.7.26
    bash /root/nexus-update-2.7.26/apply-node-traffic-update.sh /opt/3xui-aggregator

Укажите реальный каталог, например /opt/3xui-aggregator-vp. Helper выполняет preflight, запрашивает YES, останавливает aggregator, сохраняет backup, переносит файлы и пересобирает. Внешние DATA_DIR/control/workspaces/volumes сохраните отдельно. Подробности systemd и согласованного отката — в [инструкции 2.7.25](UPDATE_2.7.25.md). В БД автоматически добавляется nodes.api_connect_ip с пустым значением. Старые узлы используют DNS до явного заполнения поля. Существующие данные/клиенты миграция не пересоздаёт.

Полные исходники: Nexus-Panel-2.7.26-source.zip. Кнопка обновления из публичного репозитория получит эти изменения только после публикации исходников.

## Проверки

Целевые тесты охватывают синхронизацию, сохранение Endpoint, перезапуск, отказ при неверном CSRF, недоступное API, формат boolean, диапазоны AWG, token/password через закреплённый API, исходный Host и DNS-предупреждения. Настоящий локальный HTTPS-тест проверяет SNI и отказ при несовпадающем доверенном сертификате. Browser UI проверен в Edge на 1440/390; снимки просмотрены.

Полный набор: 273 теста, 244 pass / 10 прежних fail / 19 skip. Имена fail совпадают с 2.7.25; новых нет. Это прежние проблемы Python PATH, VM-фикстуры, статических ожиданий inbound/CSS/grace/autoselect и workspace RBAC. Полный проект не объявляется полностью зелёным. Подробности и журналы — PROJECT_HANDOFF.md.

Настоящие VPS, Docker build, iPhone и VPN handshake не проверялись. Для окончательной проверки используйте обновлённую подписку после выбора правильного API IP, затем сравните Endpoint и параметры AWG с работающим отдельным конфигом.
