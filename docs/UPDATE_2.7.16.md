# Nexus 2.7.16 — UDP/443 для обычных узлов 3x-ui

21 октября 2026. Накопительный локальный патч для Nexus 2.7.7–2.7.15. Не установлен на production и не опубликован в GitHub. Устанавливается на **сервер Nexus**, не на серверы нод. DNS/routeOnly и прежние доработки входят в архив.

## Как пользоваться

1. Установить патч Nexus с резервной копией.
2. «Узлы» → добавить или изменить обычный узел **3x-ui** → «Разрешать UDP/443 · Vision / Mux».
3. По умолчанию галочка включена, в том числе у существующих обычных 3x-ui узлов после миграции. Для отдельного узла можно снять и сохранить.
4. Обновить подписку **Nexus** в приложении и переподключиться. Старый скачанный профиль сам по себе не изменится. Для JSON работает настройка flow и имеющегося Mux; для обычной SUB/VLESS — только flow (ссылка не несёт Mux).
5. Сравнить на одном узле, в одной сети, сначала с галочкой, затем без неё. Не менять DNS и transport одновременно: так можно понять, что влияет на результат.

Нужен клиент с поддержкой соответствующего flow Xray. Если приложение не принимает `xtls-rprx-vision-udp443`, выключить галочку для его узла и обновить подписку; не удалять flow сервера и не менять ключи. Работа в сторонних ядрах этим выпуском не подтверждена.

## Что именно меняется

- Только обычные узлы с типом `3xui`. **Remnawave, его клиентские профили и серверные каскады этим переключателем не меняются. Их UDP/443 на рабочих серверах не проверялся; считать его включённым нельзя.**
- Для VLESS RAW/TCP + REALITY/TLS, если исходный пользователь уже использует Vision, клиентский flow: включено → `xtls-rprx-vision-udp443`; выключено → `xtls-rprx-vision`.
- Если Mux уже задан настройками Nexus или наследованием из 3x-ui, в клиентском JSON меняется только `xudpProxyUDP443`: включено → `skip` (собственная передача UDP протокола VLESS), выключено → `reject`. Поля enabled/concurrency/xudpConcurrency не меняются. Переключатель **не включает Mux** и не добавляет его, когда его нет.
- Для XHTTP/WS/gRPC Vision не подставляется. Для VLESS без Vision и без Mux переключатель ничего не меняет: это не универсальный запрет UDP/443 и не firewall. Другие порты UDP и правила direct/proxy не переписываются.
- У автоподключения каждый кандидат сохраняет собственную политику; общий запрет на весь пул не добавляется. Это не проверка фактической UDP-доступности каждого кандидата.
- UUID, адрес сервера, ключи REALITY, SNI, срок, лимиты и серверный inbound остаются прежними. Старое открытое окно редактора без новых полей не сбрасывает выбор. Изменение политики повышает ревизию подписки. Копия узла наследует выбор, backup сохраняет его.

## Нужно ли менять 3x-ui

Для обычного VLESS Vision **обычно достаточно обновить профиль, выдаваемый Nexus**. На сервере остаётся `xtls-rprx-vision`: суффикс `-udp443` — клиентская настройка, Xray удаляет его перед отправкой flow серверу. Это подтверждается [исходником Xray](https://github.com/XTLS/Xray-core/blob/main/proxy/vless/outbound/outbound.go) и [описанием Vision](https://xtls.github.io/en/config/outbounds/vless.html).

Входящий UDP/443 в firewall открывать для VLESS/TCP не требуется: внешний транспорт остаётся TCP на VPN-порту, UDP идёт внутри него. Но если на сервере запрещён **исходящий** UDP, есть правило Xray `network: udp → block` или ограничение хостинга, Nexus этот запрет не отменяет. Тогда потребуется отдельная проверка сервера. Подписка напрямую из 3x-ui, минуя Nexus, также не получит переключатель Nexus.

Обычный Vision намеренно ограничивает UDP/443 для перехода QUIC на HTTPS/TCP. Его разрешение не означает ускорение всех приложений или гарантированное устранение зависания WhatsApp; звонки могут использовать и другие UDP-порты. [Mux/XUDP](https://xtls.github.io/en/config/outbound.html#muxobject).

## Установка

До установки сохранить исходники, `.env` и все базы Nexus. Внешние DATA_DIR/control/workspaces/volumes сохранить отдельно: helper архивирует каталог приложения, не внешние данные.

Для существующей Docker-установки на сервере Nexus:

```bash
unzip Nexus-Panel-2.7.16-udp443-patch.zip -d /root/nexus-udp443-2.7.16
cd /root/nexus-udp443-2.7.16
bash apply-node-traffic-update.sh /opt/3xui-aggregator
```

Последний путь заменить реальным каталогом Nexus. Helper проверяет каталог/manifest, запрашивает YES, временно останавливает только aggregator, сохраняет backup каталога и пересобирает сервис. Старые ZIP предварительно устанавливать не нужно.

Для systemd: остановить свой сервис Nexus, сохранить полный backup, перенести файлы по PATCH_FILES.txt с сохранением путей, выполнить `npm ci --omit=dev` и запустить сервис. Имя сервиса зависит от установки.

Откат: остановить Nexus, восстановить согласованный backup исходников и баз, пересобрать/запустить. Для простого возврата стандартного Vision достаточно снять галочку, сохранить и обновить подписку. При полном откате к 2.7.15 обновление подписки также обязательно.

`panel-script-v1.sh --update` этот архив не устанавливает; автоматическое обновление Nexus не получает неопубликованный ZIP.
