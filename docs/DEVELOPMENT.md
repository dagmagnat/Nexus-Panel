# Локальная разработка

## Быстрый старт

Требования: Node.js 22 LTS, npm и современный браузер.

```bash
npm ci
npm run dev
```

Первый запуск автоматически создаёт:

- `.env.development` с отдельными случайными секретами и dev-паролем;
- `data-dev/` с отдельной SQLite-базой;
- BrowserSync-прокси на `http://localhost:3001`;
- BrowserSync UI на `http://localhost:3002`.

Логин и сгенерированный пароль печатаются в терминал при каждом `npm run dev`.

## Что обновляется автоматически

- `views/**/*.ejs` — браузер перезагружается;
- `public/css/**/*.css` — стили обновляются;
- `public/js/**/*.js` — браузер перезагружается;
- `app.js`, `lib_crypto.js`, `lib_vpn_manager.js` — Node перезапускается через nodemon.

Рабочий URL для разработки — `http://localhost:3001`, а не прямой порт 3000.

## Безопасность dev-окружения

Dev-режим использует `DATA_DIR=./data-dev`, поэтому не должен затрагивать production-базу `data/app.db`.

Не копируйте production `.env` и production SQLite в рабочую папку без отдельной необходимости. Для воспроизведения ошибки сначала используйте обезличенный backup.

## Команды

```bash
npm run dev          # сервер + live reload
npm run dev:server   # только Node/nodemon
npm run dev:ui       # только BrowserSync
npm run check        # синтаксическая проверка backend
npm start            # обычный запуск без live reload
```

## Как делать UI-изменения быстро

1. Найдите экран в `docs/UI_MAP.md`.
2. Меняйте структуру страницы в соответствующем `views/*.ejs`.
3. Для локальных стилей используйте новый тематический файл, `public/css/stage90.css`: он уже подключён последним в `views/partials_header.ejs`.
4. Общую навигацию и оболочку меняйте в `views/partials_header.ejs`.
5. Общий браузерный JavaScript находится в `views/partials_footer.ejs`; новый переиспользуемый код лучше выносить в `public/js/`.
6. Проверяйте ширины 360, 768, 1280 и обе цветовые темы.

Не рекомендуется продолжать наращивать `style.css`, `redesign.css` и огромный inline-script в footer. Новые компоненты лучше постепенно выносить в отдельные CSS/JS-файлы с понятными именами.

## Визуальный UI inspector

В development-режиме в правом нижнем углу появляется кнопка **UI inspector**.

1. Нажмите кнопку.
2. Выберите элемент на странице.
3. Инспектор покажет предполагаемый EJS-шаблон и точный CSS-селектор.
4. Нажмите «Копировать задачу» и допишите, что должно измениться.

Такой текст можно сразу передавать разработчику или AI без неоднозначных описаний расположения элемента.
