# Nexus 2.7.28 — исправление Flow Vision

Обновление исправляет создание и восстановление пользователей обычных узлов 3x-ui. «Full Vision» из запроса трактуется как поле Flow со значением xtls-rprx-vision.

## Причины

Ранее нормализация применялась только к новому Clients API. Ветка старого inbound API могла отправлять пустой или неподходящий Flow. При attach уже существующей глобальной записи её пустой Flow сохранялся, после чего операция «создать недостающих» пропускала найденного пользователя. Ещё одна ошибка: генератор подписки подставлял Flow первого клиента inbound, если у нужного пользователя Flow был пустым. Поэтому подписка могла содержать Vision, а серверная запись — нет.

## Новое поведение

- Обычный VLESS TCP/RAW с TLS или REALITY получает стандартный xtls-rprx-vision при создании и обновлении через старый и новый API.
- «Создать недостающих пользователей» также исправляет пустой Flow уже существующих клиентов, включая attach глобальной записи. UUID, лимит, срок, subId и другие данные существующего клиента при отдельном исправлении Flow сохраняются.
- Исправление Flow адресуется выбранному inbound. В новом глобальном API используется inboundIds-фильтр; при редактировании несовместимого транспорта общий Flow не очищается. Настройки XHTTP/AWG других привязок не должны заменяться Flow выбранного TCP-узла.
- После создания/обновления проверяется реально сохранённый Flow выбранного inbound. Если API отвечает успешно, но Vision не сохранён, Nexus сообщает ошибку вместо подтверждения успеха.
- При генерации SUB/JSON используется Flow нужного пользователя. Пустое значение больше не маскируется Flow другого человека. После изменения параметров в исходной панели обновите параметры узла и подписку.
- Повторная массовая операция не переписывает исправные Flow и не создаёт повторных пользователей. В результате операции показывается число обновлённых записей.

Vision не назначается принудительно обычному XHTTP без VLESS Encryption, WS, gRPC, AmneziaWG или inbound с явным disableFlow. Для XHTTP с VLESS Encryption сохраняются существующие правила совместимости. Provider-managed H1Cloud не переводится на принудительный Flow. Понижение версии ядра не выполняется автоматически.

## Установка

Архив содержит только файлы, изменённые относительно 2.7.26, включая доработку устройств AWG из 2.7.27. Подходит поверх 2.7.26 или 2.7.27, без предварительной установки промежуточного патча. Это не полный проект и не установщик на чистый сервер.

Распакуйте архив в отдельную папку на сервере и выполните:

```bash
cd /root/nexus-2.7.28
sudo bash apply-vision-update.sh /opt/3xui-aggregator
```

Вместо последнего пути укажите каталог вашей установленной панели с .env и docker-compose.yml. Скрипт делает резервную копию папки установки рядом с ней в .nexus-backups, собирает новый образ и заменяет aggregator. Внешние volumes и каталоги данных нужно резервировать отдельно. Compose, Caddy, .env и рабочая база архивом не заменяются. Для этого патча используйте apply-vision-update.sh, а не старые накопительные helper-скрипты.

После установки:

1. Откройте обычный TCP/REALITY узел и загрузите актуальные параметры из 3x-ui. Проверьте правильность выбранного inbound и API IP, особенно если один домен ведёт на несколько независимых панелей.
2. В списке узлов запустите «Создать недостающих пользователей» для этого узла. Операция создаст недостающих и исправит пустой Vision у существующих подходящих клиентов.
3. Проверьте число ошибок и Flow нескольких пользователей в исходной 3x-ui. Ошибку чтения/сохранения нельзя считать успешным исправлением.
4. Обновите подписку в приложении и переподключитесь. Ручное изменение порта/ключа в подписке не заменяет серверную настройку.

## Проверки и границы

Новый HTTP-тест запускает настоящую Nexus с SQLite и имитирует старый inbound API и современную глобальную модель с отдельным Flow привязок. Покрыты создание узла с массовым добавлением, создание нового клиента, attach, исправление существующего, повтор без новых записей, сохранение квот/UUID/subId, независимый XHTTP, ошибки сохранения, отсутствие чужого Flow в подписке, CSRF, конфликт UUID и удаление из одного узла.

Дополнительно выполняются существующие проверки редактора клиентов, удаления, совместимости REALITY и AWG. Полный набор проекта имеет прежние ошибки, результаты зафиксированы в PROJECT_HANDOFF.md. Не заявляется исправление всех ошибок панели.

Новая версия подготовлена локально и не установлена на VPS. Причиной каждого минутного сетевого сбоя нельзя считать отсутствие Flow без совпадения по времени и проверки протокола. Отдельные перезапуски ядра и фильтрация оператора требуют самостоятельной диагностики. Строка Remove Inbound User при генерации конфигурации сама по себе не доказывает новое удаление клиента.
