# Исправление Docker build context — 2026-11-02

Точечная правка для существующего Nexus, включая 2.7.22. Версия приложения не изменяется. Файл .dockerignore должен находиться в корне build.context, рядом с Dockerfile. Он исключает рабочие data/control/workspaces, .env, базы с WAL/SHM, backup-архивы, node_modules и временные файлы. На хосте они сохраняются; runtime-данные продолжают поступать через существующие volumes/env_file. Compose и пути баз не меняются.

Причина инцидента: отсутствовал .dockerignore, COPY . . захватывал 5,37 ГБ, в том числе data/app.db; место закончилось при создании слоя. Игнорирование уменьшает будущий контекст/слой, но не удаляет старые образы/кэш и не гарантирует место при любом объёме исходников. Сами сообщения об ошибке не доказывают повреждение или удаление исходной базы. Образы, созданные прежде, могли содержать базу/.env — не публикуйте их.

Официальная документация: https://docs.docker.com/build/concepts/context/#dockerignore-files

## Применение на восстановленном сервере

Пользователь подтвердил running(2), каталог /opt/3xui-aggregator, 6,6 ГБ свободного места. Не требуется повторно останавливать работающую панель, чистить volumes или повторять полный установщик. Сохраните имеющийся backup данных вне образа.

Загрузите Nexus-Docker-context-fix-20261102.zip в /root. Если Compose использует другой context/Dockerfile, применяйте файл к фактическому context. Специфичный Dockerfile.dockerignore имеет приоритет над общим .dockerignore: если такой файл существует, сначала объедините исключения с ним, не считайте общий файл достаточным.

```bash
cd /opt/3xui-aggregator
test ! -f Dockerfile.dockerignore || { echo 'Найден Dockerfile.dockerignore: сначала объедините исключения'; exit 1; }
if [ -f .dockerignore ]; then
  cp -a .dockerignore ".dockerignore.before-$(date +%Y%m%d-%H%M%S)"
fi
unzip -o /root/Nexus-Docker-context-fix-20261102.zip .dockerignore
```

Не выполняйте сборку, если распаковка завершилась ошибкой. Сначала отдельно соберите образ, не останавливая текущий контейнер:

```bash
docker compose --progress plain build aggregator &&
docker compose up -d --no-deps --no-build aggregator
docker compose ps
docker compose logs --no-color --tail=40 aggregator
```

При неудачной сборке команда после && не выполнится, существующий контейнер останется запущен. В случае успешной сборки up пересоздаст только aggregator; возможен краткий перерыв, Caddy не пересоздаётся. Проверьте передачу build context: она должна существенно уменьшиться относительно прежних 5,37 ГБ. Точный размер зависит от каталога. Если передаются гигабайты — не продолжайте установщик, проверьте context и Dockerfile-specific ignore.

Не удаляйте data, .env или volumes. Старые активные образы автоматически не очищаются этой правкой; вопрос очистки обсуждается отдельно после стабильного запуска. Откат .dockerignore возвращает риск попадания базы в образ, а не восстанавливает предыдущий образ приложения.
