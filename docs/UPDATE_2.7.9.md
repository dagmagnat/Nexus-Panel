# Nexus 2.7.9 — страницы пользователей, HWID и лимиты Remnawave

## Коротко

- Пользователи: 20 на странице по умолчанию; снизу 20/50/100/150/200/Все и номера страниц. Поиск, узел, группы, метки и сортировка применяются ко всему каталогу до пагинации. «Выбрать все» выбирает текущую страницу. Для всех пользователей явно выберите «Все»; большой список будет тяжелее.
- Статистика расхода в браузере запрашивается только для текущей страницы. Устройства, метки, модальные редакторы и лимиты остальных клиентов не сериализуются в HTML. Счётчики верхних карточек остаются общими.
- Устранён порядок проверки Remnawave: новый общий лимит синхронизируется до отказа по старому `LIMITED`. Настоящий исчерпанный общий лимит, истёкший срок и `DISABLED` не обходятся.
- После сохранения общего лимита он читается обратно из API: неподтверждённое изменение показывает ошибку, а не ложный успех.

## Как задать отдельные квоты

1. Пользователи → редактор → **Общий лимит трафика = 0**, если общего ограничения не нужно.
2. Ниже у каждого узла задайте свою квоту: например, Германия 5, Финляндия 50 ГБ.
3. В настройках каждого Remnawave-узла Nexus укажите UUID его физической ноды и отдельный Internal Squad, доступный только этой ноде. Разные названия сквадов недостаточны: важна реальная привязка inbound к физическим нодам.
4. Сохраните, откройте Трафик → Обновить с узлов. Проверьте предупреждения. Если хотите начать расход с нуля, явно сбросьте выбранную квоту после успешного сбора.

У Remnawave `trafficLimitBytes` — лимит общего пользователя в этой панели. Поэтому при независимых квотах native-поле будет 0, а 5/50 ГБ контролирует Nexus по физической ноде через эксклюзивный сквад. Дневной учёт и особенности сброса описаны в [2.7.8](UPDATE_2.7.8.md). Общий сквад не отключается автоматически: Nexus показывает ошибку, чтобы не затронуть другие серверы. Отдельные CDN-методы на одной физической ноде этот API статистики не разделяет.

Если в общем поле Nexus задано 50, именно 50 ГБ передаются удалённому пользователю; квоты отдельных узлов при этом сохраняются отдельно. Пользователь, чей старый общий лимит был 5 и статус `LIMITED`, вновь получает `ACTIVE` только если новый общий лимит ещё не исчерпан, локальный клиент включён и срок действует. История и счётчик расхода не сбрасываются этим изменением.

Управление независимыми квотами требует работающего Nexus: фоновый опрос примерно раз в минуту, не мгновенная блокировка каждого байта. Без доступа к API остаётся последний известный расход и предупреждение.

## Смена приложения / HWID

Настройки → Подписки и приложения → **2. Устройства и блокировки** → «Смена приложения при обновлении подписки».

Режимы:

1. **Ручное удаление / сброс** — по умолчанию. Обновление известных приложений не меняет остальные привязки.
2. **Заменить одну старую привязку** — если лимит заполнен и пришёл новый HWID, заменяется ровно одна привязка без обновления дольше указанного срока. Значение по умолчанию 72 часа, допустимо 1–720. Свежие устройства не удаляются, свободные слоты не затрагиваются, чужие клиенты не затрагиваются. Реестр, уже превышающий лимит после его уменьшения, требует ручного сброса.
3. **Полный сброс при каждом HWID-обновлении** — остаётся только запрашивающее приложение. Для сохранения нужно отдельно подтвердить ослабление лимита. Несколько устройств смогут поочерёдно обновлять одну ссылку: строгого ограничения числа используемых устройств этот режим не обеспечивает.

Рекомендую режим 2, если вы принимаете замену по времени обновления. Сервер **не видит удаление приложения**, а последняя выдача подписки не доказывает отсутствие VPN-соединения. При автообновлении старого приложения его привязка останется свежей. Возможность немедленно и точно узнать об удалении без поддержки самого приложения отсутствует.

Браузер без HWID, HEAD-проверка, отключённый/истёкший клиент не освобождают слоты. Изменения регистрации выполняются одной транзакцией. Удаляется только реестр Nexus: уже выданные ключи не отзываются, независимый реестр HWID Remnawave не обнуляется. Лимит IP на ноде — другой механизм. Для обязательного учёта выберите «Требовать HWID» и используйте совместимые приложения; это не делает два приложения на одном телефоне одним HWID.

## Remnawave 3.3.0

Проверен официальный [контракт обновления 3.3.0](https://github.com/remnawave/backend/blob/3.3.0/libs/contract/commands/users/update-user.command.ts) и [3.4.4](https://github.com/remnawave/backend/blob/3.4.4/libs/contract/commands/users/update-user.command.ts): альтернативные идентификаторы — `id` или `username`; `trafficLimitBytes: 0` означает безлимит. Nexus предпочитает числовой ID, когда API его возвращает, и не отправляет одновременно username как второй ключ в PATCH. Старые сохранённые идентификаторы могут разрешаться через сохранённое имя пользователя. UUID-fallback для старых ответов сохранён, но независимый node-scoped учёт до 3.3 не проверен. Отдельный переключатель между одинаковыми контрактами не требуется; несовместимые будущие API не считаются автоматически поддержанными.

API-фикстура в HTTP-тесте требует строго один числовой ID и проверяет реальную форму редактирования 5→50, старый LIMITED и сохранение здорового узла в той же выдаче подписки. Это локальные тесты, не проверка настоящего сервера пользователя.

## Установка

Патч накопительный для имеющейся Nexus **2.7.7 / 2.7.8**, включает предыдущий независимый учёт и новый интерфейс. Применять **только на сервере Nexus**, не на нодах и не запуском `panel-script-v1.sh --update`. GitHub не обновлялся; публичная команда обновления может скачать другую версию.

Загрузите архив на сервер Nexus и выполните для стандартного Docker-развёртывания:

```bash
unzip Nexus-Panel-2.7.9-clients-patch.zip -d /root/nexus-clients-2.7.9
cd /root/nexus-clients-2.7.9
bash apply-node-traffic-update.sh /opt/3xui-aggregator
```

Укажите действительный каталог Nexus вместо `/opt/3xui-aggregator`, если он другой. Помощник проверяет целевое приложение, просит YES, останавливает только `aggregator`, сохраняет весь каталог с `.env` и базами в резервную копию рядом, накладывает `PATCH_FILES.txt`, пересобирает контейнер. Не удаляет клиентов, историю, панели или ноды. Если DATA_DIR/control/workspaces/volumes находятся вне этого каталога, сохраните их отдельно до запуска.

Для systemd: остановить только Nexus, сохранить весь каталог приложения и все внешние базы/пространства, скопировать файлы из PATCH_FILES.txt по их путям, выполнить `npm ci --omit=dev`, запустить свой сервис. Имя сервиса helper не угадывает.

Откат: остановить Nexus, восстановить исходники **и базы** из полной резервной копии, затем пересобрать/запустить. Не заменять базу работающего процесса. Удалённые действия на Remnawave/XUI откатом Nexus не отменяются. Сначала рекомендуется проверить копию данных.
