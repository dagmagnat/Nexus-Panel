# Nexus 2.7.27 — персональный AmneziaWG для устройств

Это архив **только изменённых файлов относительно 2.7.26**. Он не предназначен для установки на чистый сервер или поверх более старой версии. Режим по умолчанию выключен. Релиз подготовлен локально; кнопка обновления из GitHub не получит эти файлы, пока они не опубликованы в репозитории.

## Установка

Распакуйте ZIP в отдельную папку на сервере. В установленном Nexus должна быть версия 2.7.26. Пример:

```bash
cd /root/nexus-awg-2.7.27
sudo bash apply-awg-devices-update.sh /opt/3xui-aggregator
```

Замените последний аргумент на папку вашей установки с .env, VERSION и docker-compose.yml. Скрипт проверит версию, остановит только aggregator для согласованной резервной копии, снова запустит старый образ и соберёт новый. Замена контейнера выполняется после успешной сборки. Проверяйте итоговые логи контейнера: запуск контейнера сам по себе не доказывает готовность приложения.

Полная копия папки установки сохраняется рядом с ней в .nexus-backups с закрытыми правами. Каталоги данных, подключённые извне папки установки, и внешние Docker volumes следует резервировать отдельно. Compose, Caddy, .env и база этим архивом не заменяются. Нужны свободное место для резервной копии и сборки и рабочий Docker Compose. Старый накопительный apply-node-traffic-update.sh для этого delta-архива не используется.

## Включение и использование

1. Проверьте подключение AWG-узлов. Если один API-домен направлен на несколько независимых серверов, задайте точный «IP сервера для API» из 2.7.26. Ручной Endpoint остаётся отдельным клиентским адресом и не меняется.
2. Откройте Настройки → Подписки и приложения → Устройства и блокировки. Включите «Отдельный AWG-конфиг на устройство» и сохраните.
3. У клиента должны быть назначены включённые AWG-узлы. Лимит устройств берётся из существующего поля клиента: 2, 5 и т. д.; 0 означает без лимита.
4. Приложение с HWID обновляет прежнюю подписку. На каждом назначенном AWG-узле Nexus создаёт отдельную удалённую учётную запись для устройства. Повторные обновления и перезапуск Nexus используют прежний peer, ключ и IP, пока учётная запись существует в исходной панели.
5. Для приложения без HWID откройте Пользователи → клиент → Устройства → «Создать ссылку устройства без HWID». Передайте его персональную JSON/SUB-ссылку либо скачайте AWG .conf для нужного узла. Создание ссылки сразу занимает один слот. Приложениям, не поддерживающим AWG в подписке, нужен .conf и совместимый AWG-клиент.

Один HWID на нескольких AWG-узлах занимает один слот Nexus; удалённый peer создаётся отдельно на каждом узле. Имена удалённых записей начинаются с nxawg_, включают имя клиента и номер устройства. Эти записи не импортируются как самостоятельные обычные пользователи Nexus.

Режим принудительно использует ручное удаление/сброс устройств. Автоматический полный сброс при каждом обновлении подписки нарушил бы привязку и лимит. Приложения могут присылать разные HWID на одном телефоне; удаление приложения серверу не видно. Если HWID отсутствует, общая ссылка сохраняет доступные другие протоколы и показывает пояснение вместо общего AWG-ключа.

## Миграция, отзыв и ограничения

Перед первой персональной выдачей общий AWG-клиент отсоединяется только от выбранного AWG inbound. Его VLESS и другие подключения сохраняются. При смене API-сервера сначала отзываются персональные записи прежнего сервера; до подтверждения новые ключи не выдаются. Удаление исходного peer вручную в 3x-ui может потребовать повторного создания и нового импорта .conf.

Удаление устройства, сброс устройств, удаление назначения узла/клиента/узла сохраняют очередь отзыва. При доступном API удаление устройства пытается выполнить отзыв сразу. При недоступном API интерфейс сообщает, что отзыв ещё не подтверждён. Старый ключ до восстановления API может оставаться рабочим; выдача нового AWG на этом узле ждёт подтверждения. Очередь переживает перезапуск и повторяется при запуске и примерно каждые 30 секунд. Ошибки видны рядом с настройкой режима. Доступность исходного API необходима для операций с ключами.

Новый режим проверяет срок, включение клиента/узла/назначения и лимит устройств при выдаче и в фоне. После уменьшения лимита устройства сверх первых допустимых слотов отключаются, после увеличения могут использовать прежние записи. Уже выданный конфиг не исчезает с телефона; меняется его разрешение на сервере.

Персональная ссылка — секрет доступа. .conf содержит приватный ключ. Протокол не доказывает физическую идентичность устройства: копирование ссылки/HWID/готового ключа на другой телефон технически возможно. Решение разделяет ключи и позволяет адресно их отзывать, но не обещает запрет копирования или точный подсчёт людей.

## Трафик и квоты

Расход всех персональных peers суммируется в существующую квоту клиента на этом AWG-узле, а не назначается полностью каждому устройству. Ранее учтённый расход сохраняется как база миграции. История расхода сохраняется после удаления устройств и сброса удалённых счётчиков. Кнопки сброса трафика Nexus обновляют локальную точку отсчёта, не сбрасывая общий VLESS-аккаунт исходной панели.

Остаток квоты делится между зарегистрированными персональными peers, а не резервируется по одному полному лимиту на каждый. Сначала уменьшаются прежние бюджеты, затем увеличиваются остальные. Неиспользованный остаток перераспределяется при фоновой сверке примерно каждые 30 секунд; устройство может кратковременно ждать перераспределения. При изменении счётчиков извне, удалении peer вручную или сбое связи нет атомарной гарантии учёта каждого последнего байта. Сохраняется существующая политика квот по узлам Nexus.

## Выключение и откат

Выключение настройки сначала отключает персональные AWG-записи и затем восстанавливает общую AWG-привязку. Другие протоколы сохраняются. После обратного включения те же зарегистрированные устройства используют прежние персональные записи.

Перед откатом на 2.7.26 выключите режим в 2.7.27 и дождитесь успешной фоновой сверки без ошибок. Простая замена исходников старой версией при активных персональных ключах оставит их без управления. Резервная копия базы не отзывает уже созданные ключи на удалённом сервере; сохраняйте актуальную очередь до завершения отзыва.

## Проверки

Локальные тесты используют SQLite, настоящий HTTP-сервер Nexus и имитацию API 3x-ui: отдельные ключи/IP, конкурентные обновления, лимит, общий расход, отзыв и повтор после сбоя/перезапуска, срок/отключение, смена API, персональные ссылки и .conf, смешанный VLESS/AWG. Проверен интерфейс в Edge на ширине 1440 и 390 пикселей.

Это не проверка реального AWG-handshake, сервера пользователя или физического iPhone. Полный набор проекта имеет прежние ошибки в других тестах; результаты перечислены в PROJECT_HANDOFF.md. Новая функция поставляется отдельным режимом, выключенным по умолчанию.
