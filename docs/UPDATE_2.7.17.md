# Nexus 2.7.17 — чистые ссылки, установка и список узлов

21 октября 2026. Накопительный локальный патч для установленной Nexus 2.7.7–2.7.16. На сервер не установлен, GitHub не обновлён. Старые патчи предварительно применять не требуется. Не предназначен для установки на ноды 3x-ui/Remnawave или обновления panel-script-v1.

## Ссылки подписки

Новые ссылки Nexus для обычных ключей длиной 12–128 символов (буквы/цифры/дефис/подчёркивание):

```text
https://subscription.example/ключ-клиента             JSON
https://subscription.example/ключ-клиента?format=sub  SUB
```

Пример ключа в адресе — условный: используйте уже существующие ссылки клиента в Nexus. Ключи пользователей не меняются. Старые `/json/ключ`, `/sub/ключ`, `/sub-plain/ключ` и `/happ/ключ` продолжают работать. Сначала проверьте новую ссылку на одном клиенте; массово переимпортировать подписки не нужно. Временно могут продолжать работать/отображаться ссылки, ранее сохранённые в приложении, QR-коде или сообщении Telegram.

Для коротких/необычных импортированных ключей или совпадений с системными путями Nexus сохраняет прежнюю форму ссылки: не нужно менять ID клиента ради внешнего вида URL. Для отдельных рабочих пространств сохраняется пространство имён `/s/<workspace>/ключ`; скрывать его без отдельного механизма глобальных токенов нельзя — разные базы могут содержать одинаковые ключи.

- По умолчанию JSON. `?format=sub` — обычная текстовая подписка с прежними метаданными; `?format=single` и `?node=2` — существующая выдача одного JSON-профиля. Неизвестный/повторный format отклоняется.
- Перенаправления для обычного запроса приложения нет: URL внутренне направляется в прежний обработчик, сохраняющий HWID, expiry, disabled, квоты и заголовки no-cache. При настоящем открытии браузером остаётся переход на личную страницу `/open/ключ`; `?download=1` принудительно выдаёт содержимое.
- Новые ссылки в карточке клиента, portal и Telegram формируются без /json/ и /sub/. Параметр raw/download, если интерфейс добавляет его для скачивания, не является частью ключа.
- Это косметическое упрощение, не защита от утечки ключа. Не публикуйте действующие ссылки. Ссылки, выданные непосредственно исходной 3x-ui/Remnawave, этот патч не переписывает.

## Исправления установки

1. Обязательный `build.network: host` заменён обычной сетью. При Bake больше не нужен `--allow=network.host` только ради установки Nexus. Статический Compose допускает явный opt-in NEXUS_BUILD_NETWORK, но его включение требует осознанного разрешения со стороны Docker/BuildKit и не является автоматическим fallback. Сеть работающих VPN-контейнеров не меняется.
2. `admin`/пустой пароль отклоняется до сборки и до остановки существующего приложения. Новый пароль — минимум 12 символов, максимум 72 байта. Существующий нестандартный короткий пароль не заменяется автоматически; приложение по-прежнему предупреждает о коротком пароле.
3. Пароль в .env сохраняется как буквальное single-quoted значение: $ и # не интерпретируются Compose. Для новых значений установщика одинарная кавычка и переносы строк отклоняются. Старый default пароль автоматически не генерируется и не показывается в журнале: пользователь должен заменить его сам.
4. Изменение ADMIN_PASSWORD не сбрасывает пароль уже существующего аккаунта в базе. APP_SECRET/SESSION_SECRET, базы клиентов и исходные API-токены не меняются. Установщик и обновление не отключают production-защиту.

Проверено по [Docker: переменные .env](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/) и [BuildKit/Bake network entitlements](https://docs.docker.com/build/bake/reference/#targetnetwork).

## Установка на имеющийся Docker-экземпляр

Сохраните полную копию исходников, .env и всех баз. Внешние DATA_DIR/control/workspaces/volumes, включая базы локальных 3x-ui/Remnawave, архивируйте отдельно: helper сохраняет каталог Nexus, не всё содержимое VPS.

Для экземпляра из присланного журнала:

```bash
unzip Nexus-Panel-2.7.17-clean-links-install-patch.zip -d /root/nexus-update-2.7.17
cd /root/nexus-update-2.7.17
bash apply-node-traffic-update.sh /opt/3xui-aggregator-vp
```

На другом сервере заменить последний путь реальным каталогом Nexus. Внешние домены/порты не менять только ради этой доработки. Если .env ещё содержит ADMIN_PASSWORD=admin, сначала задайте безопасный пароль и только затем запускайте helper.

Helper:

- до остановки проверяет состав патча, пароль .env и возможность миграции известных шаблонов;
- запрашивает YES и временно останавливает aggregator для полного backup каталога;
- меняет только build.network: host → default внутри aggregator (не network_mode, порты, тома или имена сервисов);
- в ограниченных публичных блоках Caddy добавляет отдельный matcher чистых ссылок и исключает административные имена; прежний respond 404 и маршруты остаются;
- Caddyfile проверяется отдельным `caddy validate`; при изменении Caddy пересоздаётся после сборки aggregator, поскольку файловый bind mount может держать старый inode;
- новые файлы приложения устанавливаются и aggregator пересобирается. Если Caddy нужно менять, но сервиса caddy нет, helper остановится до изменения установки — нужен разбор внешнего прокси.

При успешном обновлении:

```bash
cd /opt/3xui-aggregator-vp
docker compose ps
docker compose logs --no-color --tail=60 aggregator
```

Проверить, что через 20–30 секунд статус остаётся Up, открыть панель и скопировать новую JSON-ссылку тестового клиента. Старую ссылку не удалять до проверки. Caddy может кратковременно прервать подключения при пересоздании.

Резервные копии Compose/Caddy создаются дополнительно с суффиксом `.before-nexus-2.7.17-*`. Если конфигурация уже совместима, повторная миграция её не переписывает. Миграция не перезапускает сервер целиком и не меняет глобальные настройки Docker.

### Свой Nginx, Caddy или systemd

Патч не переписывает произвольную конфигурацию внешнего прокси. Если он пропускает лишь `/json/*` и `/sub/*`, дополнительно пропустите одноуровневые ключи, подходящие под `^/[A-Za-z0-9_-]{12,128}/?$`, в тот же Nexus upstream с сохранением query string. Исключите системные имена (как минимум auto-select-profiles, happ-routing, happ-routing-json, mobile-login, node-traffic); не открывайте весь путь /* к административному приложению вместо прежнего ограничения. Для уже полного reverse_proxy на Nexus новый путь проходит без отдельного правила.

При ручном обновлении остановить свой сервис, сохранить backup, перенести файлы PATCH_FILES.txt с сохранением путей, `npm ci --omit=dev`, обновить правила прокси и запустить сервис. Внешний Caddy/Nginx предварительно проверить своим валидатором. Для произвольного vhost лучше подготовить отдельный точный diff, а не применять общий sed.

## Страница узлов

Пустой список больше не растягивается на весь desktop-экран, текст имеет нормальные отступы. Автоподключение перенесено в заголовок списка, добавлена кнопка добавления первого узла, убрана инструкция перетаскивания при пустом списке. Проверены размеры 1440/390, отсутствие горизонтального переполнения и переход к форме. Изменение не создаёт узлы автоматически.

## Проверки и границы

Целевой набор: 49 тестов, 40 pass, 9 platform skip, 0 fail. Проверены чистые/старые ссылки, JSON/SUB/single/HEAD/browser, HWID-лимит, disabled, плохой format, no-cache, CSRF, настоящие отдельные workspace-процессы с одинаковым токеном и выбранным cookie другого пространства, перезапуск. Проверены shell/password literal, backup/idempotence/сохранение портов/секретов в миграции, сохранены прежние DNS/UDP443 проверки. Полный прогон Bash-helper с подставным Docker CLI требует нативных POSIX mkdir/install и на Windows пропущен; это не тест реального Docker.

Полный набор: 250 тестов, 224 pass, 9 прежних fail, 17 skip. Те же ошибки, что в 2.7.16: Python PATH ×3, VM budget, прежние ожидания inbound/CSS/grace/device-grace/RBAC. Полный набор не зелёный. Логи work/clean-links-*.log не входят в ZIP.

UI-тест запускает локальную Nexus и Edge с фикстурной учётной записью; screenshots просмотрены. 20 EJS и JS/Bash syntax проверяются при выпуске. Docker/Bake/Caddy на реальном Linux VPS, приложения Happ/v2rayTun/INCY на телефоне, TLS вашего домена и действующие подписки production не проверялись. Успешная локальная проверка не означает деплой на ваш сервер.

## Откат

Остановить Nexus, восстановить исходники, Compose/Caddy/.env и базы из согласованной полной копии, пересобрать aggregator; Caddy при восстановлении file bind mount пересоздать. Внешние базы восстановить из отдельной копии, если они менялись. Возврат только приложения без прокси оставит новые ссылки недоступными, но старые `/json/` и `/sub/` после полного отката остаются предусмотренным вариантом.

`panel-script-v1.sh --update` этот ZIP не устанавливает. Публичный GitHub/автообновление ещё не содержит локального выпуска: применяйте выданный архив, не считайте старый bootstrap обновлённым.
